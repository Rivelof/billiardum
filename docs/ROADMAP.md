# Бильярдум: план выпуска

Этапы идут по порядку. Внутри этапа независимые задачи выполняются параллельно. Этап закрыт, когда выполнены все критерии приёмки и tester с pentester прошли без замечаний. Сроки ориентировочные.

Железа пока нет: всё разрабатывается и проверяется на симуляторе контроллера. Комплекты для пилота Андрей заказывает параллельно с M1 (доставка 2–4 недели).

---

## M0. Фундамент (около 1 недели)

**Задачи**
- Репозиторий по карте из `CLAUDE.md`, `README.md` с запуском за одну команду.
- Окружение разработки в Docker Compose: Supabase (Postgres), Mosquitto с TLS и ACL, Caddy, сервер.
- Базовые миграции: клубы, участники, ресурсы, устройства, `audit_log` (только INSERT, цепочка хешей).
- Сид для разработки: один клуб, 8 столов (5 пирамида, 3 пул), тарифы из `docs/PRODUCT.md`, раздел 9.
- `tools/device-sim/` поднимает 8 виртуальных столов и подключается к брокеру.
- Протокол утверждён: `docs/protocol.md` → v1.
- CI: линтер, юнит-тесты, проверка миграций.
- `docs/decisions.md` с решениями шага 0.

**Приёмка**
- `npm run dev` (или `make dev`) поднимает всё с нуля на чистой машине.
- Симулятор показывает 8 столов онлайн в логе сервера.
- Попытка UPDATE или DELETE в `audit_log` любой ролью падает с ошибкой.
- CI зелёный.

## M1. Стол без персонала (3–4 недели)

**Задачи**
- Движок тарифов с тестами (переход через полночь, через правило, праздники, минимум, шаг, котировка).
- Сессии и состояния стола по `docs/PRODUCT.md`, раздел 3.
- ЮKassa в тестовом режиме: СБП и карта, вебхук с перепроверкой по API, идемпотентность, двухстадийная оплата для «Без лимита».
- Мост MQTT: команды с подписью и `seq`, повторы, сверка состояния, тревоги.
- Прошивка v1 на ESP32: реле, индикатор, пищалка, датчик тока, локальный таймер, NVS, TLS, привязка, watchdog. Сборка `pio run`, тесты логики на хосте `pio test`. Симулятор повторяет поведение прошивки.
- Приложение гостя: вход (MAX, Telegram, код), экран стола по QR, оплата, экран игры, продление, «Я играю за этим столом», «Закончить игру», чек.
- Ресепшн: заявка «Оплачу на ресепшене» → «Принять оплату» (наличные и карта через терминал), сервисный свет с причиной.
- Владелец: «Сейчас», журнал с проверкой цепочки, тревоги в MAX и Web Push.
- Печать QR-наклеек PDF.

**Приёмка**
- Сценарии T1–T12 проходят на симуляторе.
- От подтверждения оплаты до `relay: true` в симуляторе p95 < 1 с.
- Ни одного способа включить свет без записи в журнале (pentester).
- Игра запускается, продлевается и завершается без единого действия в программе клуба.

## M2. Касса, бар, смены (2–3 недели)

**Задачи**
- POS ресепшена «как в магазине»: каталог, корзина, наличные со сдачей, карта через терминал, СБП по QR на экране.
- `tools/kkt-bridge/`: АТОЛ через веб-сервер драйвера, очередь чеков, повтор, статус. Штрих-М вторым.
- Бар: меню, модификаторы, стоп-лист, заказ со стола по QR, экран бара со звуком и статусами, «в счёт стола».
- Склад: приход, списание, остатки, ревизия.
- Смены: открытие и закрытие с пересчётом, расхождения, отчёт смены владельцу.
- Алкоголь скрыт из QR-меню до заключения юриста.

**Приёмка**
- Сценарии T13–T17.
- Сверка за смену сходится до копейки на тестовом дне из 50 продаж разными способами.

## M3. Бронь и уведомления (около 2 недель)

**Задачи**
- Бронь с выбором стола на плане зала, предоплата, удержание, сгорание, старт по брони через QR.
- Лист ожидания.
- Ограничение продления перед бронью.
- Цепочка уведомлений: основной канал гостя, запасной при недоставке; MAX-бот, Telegram-бот через прокси, Web Push.
- Утренняя сводка и сводка смены владельцу.

**Приёмка**
- Сценарии T18–T21.

### Пилот (параллельно с M3)
- Один клуб, 4–8 столов, монтаж электриком клуба, 2 недели.
- Метрики из `docs/PRODUCT.md`, раздел 21, отчёт Андрею раз в неделю.
- Прошивка в клубе обновляется только с «да» Андрея, по одному столу, на свободных столах.

**Задачи**

- «Подтвердить клуб», «Добавить клуб», заявки гостей в клубы без программы с передачей оператору.
- Заявки клубов на программу (`leads`) с уведомлением Андрею.
- Бильярдум+: профиль, рейтинг Эло с подтверждением партий без персонала, таблицы, «Ищу соперника», друзья, достижения.

## Сценарии для tester

Все сценарии проходят на симуляторе контроллера и в браузере.

| № | Сценарий | Ожидаемо |
|---|---|---|
| T1 | Гость сканирует QR, платит 2 часа по СБП | свет < 1 с после вебхука, таймер 2:00:00, чек |
| T2 | Оплата «на ресепшене» наличными | заявка на экране ресепшена, после «Принять» свет, чек ККТ в очереди |
| T3 | Продление за 3 минуты до конца | новый остаток, сигналы конца игры сдвинулись |
| T4 | Время вышло, гость молчит | T−5 индикатор, T−1 мигание, льгота 2 мин, свет гаснет, сессия закрыта |
| T5 | Связь с контроллером пропала посреди игры | контроллер доигрывает время и гаснет сам; после связи `offline_session_finished` |
| T6 | Связь пропала, гость оплатил продление | команда ждёт в очереди; связь вернулась до конца льготы — свет продлён; не вернулась — свет погас по локальному таймеру, после связи гость выбирает «Продолжить игру» или «Вернуть деньги за неотыгранное время» |
| T7 | Перезагрузка контроллера посреди игры | свет возвращается после `session.resume`, остаток верный |
| T8 | Повтор старой команды `session.extend` | `replayed_seq`, свет не продлён, событие в журнале |
| T9 | Команда с неверной подписью | `bad_sig`, тревога |
| T10 | Ток при выключенном реле (свет в обход) | `bypass_detected`, тревога владельцу сразу |
| T11 | Ресепшн включает сервисный свет | без причины нельзя; с причиной свет на время, запись в журнале, уведомление владельцу |
| T12 | Два гостя одновременно на свободный стол | первый удерживает стол 3 мин, второй видит отказ |
| T13 | Продажа бара наличными со сдачей | чек ККТ, остаток склада уменьшился |
| T14 | ККТ выключена во время продажи | продажа сохранена, `receipt_pending`, предупреждение, чек пробит после включения |
| T15 | Заказ бара со стола «в счёт стола» | заказ на экране бара, счёт закрывается при уходе |
| T16 | Закрытие смены с недостачей 500 ₽ | расхождение в отчёте, уведомление владельцу |
| T17 | Повторный вебхук ЮKassa на тот же платёж | одна оплата, одна сессия |
| T18 | Бронь с предоплатой, гость не пришёл | удержание 30 мин, бронь сгорает, предоплата по правилам клуба |
| T19 | Гость перед бронью пытается продлить через время брони | продление ограничено «до 20:55» |
| T20 | Стол освободился, есть очередь | первый получает предложение на 5 минут |
| T21 | MAX-бот не доставил напоминание | ушло в запасной канал |
| T22 | Два игрока подтверждают партию 8:5 | рейтинг пересчитан у обоих |
| T23 | Четвёртая партия одной пары за день | в рейтинг не засчитана |
| T24 | Запись на турнир с рейтингом выше лимита | отказ с объяснением |
| T25 | Клуб без программы, заявка гостя | заявка в клуб, через 15 мин без ответа — оператору |

## Фокус pentester

Три атакующих, как в файле агента:
- **Гость, который хочет играть бесплатно:** подмена суммы, повтор вебхука, продление чужой сессии, старт по чужой брони, подделка `initData`, перебор кодов столов, игра после конца времени.
- **Ресепшн, который хочет взять наличку мимо кассы:** свет без оплаты, сервисный свет как бесплатная игра, отмена после оплаты, удаление позиции из чека, правка журнала, закрытие смены без пересчёта.
- **Посторонний:** доступ к данным другого клуба, MQTT без ключей, подделка команды контроллеру, кража ключей ЮKassa клуба, утечка телефонов гостей в логах.

## Инструменты для Claude Code

Включить до начала M0:
- **frontend-design** и **Design** (Anthropic) — вёрстка по `docs/DESIGN.md`, проверка доступности и текстов интерфейса.
- **supabase** (официальный) — навыки по Postgres, RLS и миграциям. Проект self-hosted, поэтому подключение к облачному Supabase через MCP не используем, нужны навыки.
- **securitymaxxing** — по желанию, как дополнение к pentester: проверки по OWASP с указанием файла и строки.
- **Playwright MCP** для tester: `claude mcp add playwright npx @playwright/mcp@latest`.
- **PlatformIO** для firmware: `pip install platformio`.
