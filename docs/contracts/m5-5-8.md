## M5.5 «Сети»

190. **Сеть** — группа клубов одного владельца (`bl.networks`, клуб входит не больше чем в одну сеть). Создаёт владелец, добавляет только свои клубы.
191. **Единые тарифы и меню сети.**
    - Владелец сети ведёт шаблон тарифов и меню на уровне сети.
    - Клуб наследует шаблон; переопределить можно, только если сеть разрешила («жёсткий» или «мягкий» шаблон).
    - Изменение шаблона в `live` — ручное действие с причиной, уведомление владельцу, журнал в каждом клубе.
    - Цены — копейки, правила тарифов — по местному времени каждого клуба.
192. **Роль «управляющий сети»** видит и управляет всеми клубами сети как управляющий, без денег по способам оплаты и экспорта (как управляющий клуба, №166).
193. **Сравнение клубов** на дашборде: вкладка «Сеть» — таблица клубов по ключевым плиткам, рейтинг по загрузке и выручке со стола.
194. **План подписки «Сеть»** (PRODUCT §17, ~1 190 ₽ за стол) — в базе планов (№180), включается для клубов сети; цену задаёт Андрей.
195. **Франшиза** (франчайзер видит агрегаты чужих владельцев) — в бэклог: нужны договор и правила доступа к ПДн.

Приёмка:
- **T41.** Шаблон тарифа сети применяется в двух клубах с разными поясами, переопределение по правилам шаблона, журнал и уведомления.
- **T42.** Управляющий сети, сравнение, изоляция чужой сети, подписка «Сеть».

## M5.6 «Прогноз, часы пик, износ сукна»

196. **Прогноз загрузки** — по дню недели и часу: медиана за последние 8 недель из `stats_hourly`, с поправкой на праздники клуба. Показывается на вкладке «Зал» рядом с тепловой картой. Подпись «прогноз», без обещаний точности.
197. **Подсказки по цене** — только подсказки, автоматически цены не меняются: «В будни 14–17 загрузка 12 % — подумайте о дневной цене», «В пятницу 20–23 очередь — можно поднять цену».
198. **Обслуживание столов.**
    - Владелец или управляющий отмечает событие: замена сукна, шаров, резины бортов, выравнивание — дата, стол, комментарий, стоимость; стоимость идёт в кассу управляющего расходом.
    - Счётчик часов игры с последней замены (из `stats_hourly`).
    - Порог по виду — настройка клуба, по умолчанию сукно 1 500 ч, шары 3 000 ч.
    - При достижении порога — уведомление управляющему и владельцу, не тревога.
    - Таблица «Столы» на дашборде показывает «часы с замены сукна».

Приёмка:
- **T43.** Прогноз на синтетической истории 8 недель совпадает с расчётом; подсказки появляются по порогам.
- **T44.** Обслуживание — событие, счётчик, порог, уведомление, расход в кассе.

## M5.7 «Публичный API для клубов»

199. **Ключи API клуба.**
    - Создаёт владелец, имя и права (`scopes`).
    - Ключ показывается один раз, в базе — только хеш.
    - Отзыв ключа; журнал `api_key.*`.
    - Не больше 5 активных ключей на клуб.
    - Заголовок `Authorization: Bearer blk_…`.
200. **Только чтение в первой версии.** Права:
    - `tables:read` — столы и статус сейчас;
    - `tariffs:read` — цены сейчас и по расписанию;
    - `availability:read` — свободные интервалы для брони;
    - `sales:read` — продажи и оплаты за период, агрегаты как в CSV дашборда;
    - `bookings:read` — брони без ПДн: время, стол, статус, источник.
    
    Создание броней и продаж через API — в бэклог: нужны оплата и личность гостя.
201. **Исходящие вебхуки клуба.**
    - Адрес https, события `session.started`, `session.ended`, `booking.created`, `booking.canceled`, `shift.closed`.
    - Подпись HMAC-SHA256 общим секретом (показывается один раз), заголовки `X-Bl-Signature` и `X-Bl-Timestamp`.
    - Повторы с ростом паузы до 24 ч, журнал доставок.
    - **Без ПДн гостей.**
    - Адрес не может вести во внутренние сети (защита от SSRF).
202. **Лимиты:** 600 запросов в минуту на ключ, 60 на маршруты продаж. Версия в пути `/api/v1/club/…`. Документация — `docs/api/club-api-v1.md` (OpenAPI-описание и примеры).

Приёмка:
- **T45.** Ключ, права, отзыв, лимиты, ответы без ПДн, данные только своего клуба.
- **T46.** Вебхуки: подпись, повторы, SSRF-адреса отклоняются.

## M5.8 «Падел-корт»

203. **Новый вид ресурса** `padel_court`, в интерфейсе — «корт».
    - Клуб может иметь и столы, и корты.
    - Слово в интерфейсе берётся из вида ресурса, код и API остаются `resource` (CLAUDE.md).
204. **Корт — по слотам.**
    - Бронь и игра блоками 60, 90 или 120 минут (настройка клуба), цена за слот по расписанию.
    - Шаг продления — слот.
    - Свет — тот же контроллер и протокол (реле освещения корта), все инварианты те же.
    - Без брони — по QR, как стол.
205. **Игроки корта.**
    - До 4 игроков в одной игре: «Я играю на этом корте», как у стола.
    - Разделение оплаты между игроками — в бэклог.
    - Рейтинг Бильярдум+ для падела — в бэклог: своя дисциплина и правила.
    - На сайте-агрегаторе — фильтр «падел».

Приёмка:
- **T47.** Клуб с 2 кортами и 4 столами: тарифы по слотам, бронь и старт по QR, свет, продление слотом, отчёт смены и дашборд по видам ресурсов.
- **T48.** Каталог и тексты «корт»/«стол» по виду ресурса.
