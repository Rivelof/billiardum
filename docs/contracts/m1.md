# Контракты M1 «Стол без персонала»

Автор: оркестратор. Черновик до закрытия M0; уточняется по итогам M0, затем фиксируется. Отклонение — только через оркестратора.

Цель M1 (ROADMAP): сценарии T1–T12 проходят на симуляторе; от подтверждения оплаты до `relay: true` p95 < 1 с; ни одного способа включить свет без записи в журнале; игра запускается, продлевается и завершается без единого действия в программе клуба.

Ограничения среды разработки (на 21.10.2026): закрыты `api.yookassa.ru`, `dev.max.ru`, `platform-api.max.ru`, реестр PlatformIO. Поэтому:
- оплата проверяется на эмуляторе ЮKassa (`tools/yookassa-emu/`), с настоящим тестовым магазином — когда Андрей откроет сеть и даст ключи;
- вход и уведомления через MAX реализуются по документации, когда она станет доступна; до этого — интерфейс канала и вход для разработки;
- логика прошивки проверяется нативными тестами (CMake и g++), `pio run` — на машине Андрея или в CI.
В отчёте этапа каждое такое место помечается «проверено на эмуляторе».

## 1. Решения M1 (записываются в decisions.md)

1. **Рабочие сутки клуба.** Тип дня (будни, выходной, праздник) определяется по рабочим суткам, которые начинаются в `clubs.settings.day_start_local` (по умолчанию `06:00`). Ночь с пятницы на субботу 00:00–06:00 — пятничная ночь. Праздники — таблица `holidays` (нерабочие дни производственного календаря РФ), праздник считается выходным.
2. **Округление цены:** сумма считается поминутно точно (дробные копейки) и округляется один раз до целых рублей по правилу «половина вверх». Настройка клуба `price_rounding_kopecks` (по умолчанию 100).
3. **Досрочное «Закончить игру» при фиксированном времени** деньги не возвращает; гость видит это в подтверждении. «Без лимита» пересчитывается по фактическим минутам (минимум и шаг тарифа).
4. **Остановить игру может только плательщик.** Продлить — любой участник сессии.
5. **Код стола** — 10 символов Crockford Base32 (50 бит), не выводится из номера стола. `/api/t/{code}` ограничен по частоте.
6. **Деньги → свет через outbox.** Подтверждение оплаты и запись в `outbox` — в одной транзакции; обработчик сессий читает `outbox` по `LISTEN/NOTIFY` и опросу. Сбой процесса между оплатой и светом не теряет игру.
7. **Вход в PWA — через бота:** «Войти через MAX/Telegram» → бот со стартовым параметром → «Поделиться контактом» → PWA получает токен. Кодов вводить не нужно. SMS — запасной канал после M1. Для разработки — `POST /api/auth/dev`, невозможный в проде.
8. **Режим реального времени** — Server-Sent Events (`GET /api/stream`).
9. **Фронтенд:** Vite + Preact, JavaScript (ESM), без UI-библиотек. Приложения: гость `/app/`, программа клуба `/club/`.
10. **Чек при оплате стола** — `payment_mode: full_payment`, `payment_subject: service`: услуга начинается в момент оплаты. Предоплата брони и второй чек — M3. Ставка НДС и система налогообложения — настройки клуба; проверить с бухгалтером пилотного клуба.
11. **Web Push без персональных данных** в теле уведомления: только номер стола и время. Тело шифруется по стандарту Web Push.

## 3. Общие соглашения API

- Префикс `/api/`. JSON в UTF-8. Ошибка: HTTP-статус и тело `{"error":"code"}`; подробности только в логе.
- Аутентификация: cookie `bl_session` (HttpOnly, Secure, SameSite=Lax) или `Authorization: Bearer <token>` (мини-приложения). Токен — 32 случайных байта, в базе только sha256.
- Все изменяющие запросы: `Content-Type: application/json` обязателен, проверка `Origin` для cookie.
- Денежные операции принимают заголовок `Idempotency-Key` (UUID); повтор с тем же ключом возвращает тот же ответ.
- Деньги в API — целые копейки (`amount_kopecks`). Время — ISO 8601 UTC. Локальное время клуба — только в полях `*_local` с `timezone`.
- Обработчик маршрута: `export const routes = [{ method, path, auth, roles, handler }]`, где `auth` — `none` | `guest` | `staff`, `roles` — роли в клубе. `api/router.mjs` (core) подключает все `api/routes/*.mjs`, проверяет вход и роли, открывает транзакцию с контекстом клуба и передаёт `ctx = { db, user, club, roles, log, idempotencyKey }`.

### Коды ошибок (общий словарь)

`bad_request`, `unauthorized`, `forbidden`, `not_found`, `rate_limited`, `table_busy`, `table_pending`, `table_offline`, `table_service`, `quote_expired`, `quote_used`, `payment_failed`, `payment_pending`, `session_not_active`, `not_payer`, `reason_required`, `limit_exceeded`, `consent_required`, `phone_required`, `idempotency_conflict`.

## 5. Стол, котировка, оплата (backend-money)

### `GET /api/t/{code}` — без входа

```json
{
  "club": { "id": "…", "name": "…", "timezone": "Asia/Yekaterinburg" },
  "resource": { "id": "…", "number": 4, "type": "billiard_pyramid", "title": "Пирамида 12 футов" },
  "status": "free",
  "busy_until": null,
  "price_now": { "price_per_hour_kopecks": 80000, "until_local": "00:00" },
  "price_next": { "price_per_hour_kopecks": 90000, "from_local": "00:00" },
  "options": [60, 120, 180, "unlimited"],
  "my_session_id": null
}
```
`status`: `free`, `pending`, `reserved`, `busy`, `service`, `offline`. Частота: не больше 30 запросов в минуту с одного IP, иначе `rate_limited`.

### `POST /api/quotes` — гость

Запрос: `{resource_id, kind: "start"|"extend", minutes: 60|120|180|30|null, session_id?}`. `minutes: null` — «Без лимита».
Ответ: `{quote_id, amount_kopecks, minutes, valid_until, breakdown: [{from, to, price_per_hour_kopecks, amount_kopecks}]}`.
- `kind: "start"` ставит столу `pending` на 3 минуты за этим гостем. Второй гость получает `409 table_pending`.
- `kind: "extend"` считает от `paid_until` сессии; продлить может любой участник.
- Котировка держится 3 минуты и используется один раз.

### `POST /api/quotes/{id}/pay` — гость, `Idempotency-Key`

Запрос: `{method: "sbp"|"card"|"reception"}`.
Ответ:
- для `sbp` и `card`: `{payment_id, status: "pending", confirmation: {type: "redirect", url}}`;
- для `reception`: `{reception_request_id, status: "waiting_reception"}`.

Платёж в ЮKassa создаётся с ключом идемпотентности, `capture: true` (для «Без лимита» по карте — `false`, сумма за 2 часа), чеком по 54‑ФЗ, `metadata: {club_id, quote_id, kind}` и `return_url` на экран ожидания света.

### `GET /api/payments/{id}` — гость (плательщик)

`{payment_id, status: "pending"|"succeeded"|"canceled"|"waiting_for_capture", session_id?}`.

### `POST /api/webhooks/yookassa/{club_id}` — ЮKassa

- Телу не верим: берём `object.id`, запрашиваем платёж `GET /v3/payments/{id}` ключами клуба, сверяем сумму, валюту, `metadata.club_id`.
- Обработка один раз по `provider_payment_id` (уникальный индекс). Повтор вебхука — `200` без действий.
- `succeeded` или `waiting_for_capture`: в одной транзакции — статус платежа, запись журнала `payment.succeeded`, событие `outbox` `payment.confirmed` `{payment_id, club_id, quote_id, kind, session_id?, minutes, amount_kopecks}`.
- Ответ ЮKassa — всегда `200`, если платёж обработан или уже был обработан.

### Ресепшн

| Метод и путь | Кто | Запрос | Ответ |
|---|---|---|---|
| `GET /api/clubs/{club}/reception/requests` | ресепшн и выше | — | `[{id, resource_number, minutes, amount_kopecks, created_at, guest_masked_phone}]` |
| `POST /api/reception/requests/{id}/accept` | ресепшн и выше, `Idempotency-Key` | `{method: "cash"\|"card_terminal", received_kopecks?}` | `{payment_id, change_kopecks, session_id}` |
| `POST /api/reception/requests/{id}/decline` | ресепшн и выше | `{reason_code}` | `{ok: true}` |

- Наличные: `received_kopecks ≥ amount_kopecks`, сдача считается сервером.
- Принятие создаёт платёж (`cash` или `card_terminal`), задание на чек ККТ со статусом `receipt_pending` (сам мост ККТ — M2), событие `outbox` `payment.confirmed` и запись журнала `reception.accept`.
- Заявка живёт 15 минут, затем сгорает и снимает `pending` со стола.

### Эмулятор ЮKassa (`tools/yookassa-emu/`)

- HTTP-сервер с подмножеством API v3: `POST /v3/payments` (Basic `shopId:secretKey`, заголовок `Idempotence-Key`), `GET /v3/payments/{id}`, `POST /v3/payments/{id}/capture`, `POST /v3/payments/{id}/cancel`, `POST /v3/refunds`.
- Форма объектов и статусы — как у ЮKassa. **Отклоняет платёж без `receipt` или с суммой позиций, не равной сумме платежа** (`400`).
- Страница подтверждения `GET /pay/{id}` с кнопками «Оплатить» и «Отказ» отправляет вебхук на адрес клуба.
- Управление для тестов: `POST /__emu/payments/{id}/succeed`, `/cancel`, `/webhook?repeat=N`, задержка вебхука, подмена тела вебхука (для pentester).
- Включается только в разработке: `YOOKASSA_API_URL` указывает на эмулятор; в проде — `https://api.yookassa.ru/v3`.

## 6. Сессии, стол, контроллер (backend-light)

### Состояния сессии (сервер)

`active` → `ending` (≤ 5 мин) → `grace` (льгота) → `closed`; `interrupted` (контроллер доиграл без связи, а оплачено больше, чем горел свет); `cancelled`.

### Маршруты

| Метод и путь | Кто | Запрос | Ответ |
|---|---|---|---|
| `GET /api/sessions/current` | гость | — | `[session]` |
| `GET /api/sessions/{id}` | участник, персонал клуба | — | `session` |
| `POST /api/sessions/{id}/join` | гость | — | `{ok: true}` — «Я играю за этим столом» |
| `POST /api/sessions/{id}/stop` | плательщик | — | `session` |
| `POST /api/sessions/{id}/resolve` | плательщик | `{choice: "continue"\|"refund"}` | `session` — после `interrupted` (T6) |
| `GET /api/sessions/{id}/receipt` | участник | — | `{lines, total_kopecks, payments, receipt_status}` |
| `POST /api/resources/{id}/service` | ресепшн и выше | `{minutes, reason_code, reason_text}` | `{ok: true, until}` |
| `POST /api/resources/{id}/service/stop` | ресепшн и выше | — | `{ok: true}` |
| `POST /api/sessions/{id}/extend-free` | управляющий, владелец | `{minutes, reason_text}` | `session` — ручное действие |

| `POST /api/resources/{id}/identify` | владелец, монтажник | `{seconds}` | `{ok: true}` |

`session`:
```json
{
  "id": "…", "resource": { "id": "…", "number": 4 }, "status": "active",
  "started_at": "…", "paid_until": "…", "grace_until": null, "remaining_ms": 5400000,
  "unlimited": false, "is_payer": true,
  "participants": [{ "nick": "Игрок 1" }],
  "extend_limit_until": null
}
```

### Обработка `payment.confirmed`

- `kind: "start"`: создать сессию, `paid_until = now + minutes`, связать платёж, команда `session.start`.
- `kind: "extend"`: `paid_until += minutes`, команда `session.extend` (если сессия в `grace` — тоже).
- Ресурс не свободен к моменту оплаты (крайний случай) — тревога и автоматический возврат.
- Идемпотентно по `payment_id`.

### Команды контроллеру

- Только `server/mqtt.mjs`, только по протоколу v1: права и оплата → `seq` и журнал в одной транзакции → публикация. Таблица `device_commands` (`id`, `device_id`, `seq`, `type`, `body`, `status`, `attempts`, `created_at`, `acked_at`).
- Устройство офлайн: команда остаётся в очереди; при возвращении онлайн сервер шлёт не старую команду, а `session.resume` с остатком по `paid_until` (протокол §6).
- `offline_session_finished` при оплаченном остатке → сессия `interrupted`, гостю предложение «Продолжить игру» или «Вернуть деньги за неотыгранное время» (T6).
- Сверка `state` с базой, `bypass_detected`, `lamp_fault`, `bad_sig`, офлайн во время сессии > 120 с — тревоги (`server/alarms/` от core).

### Планировщик

Сигналы гостю: T−10 «Осталось 10 минут» с кнопкой «Продлить», T−1, T−0 «Время вышло, 2 минуты на продление», T+2 «Игра завершена». Закрытие сессии в T+льгота. Таймеры восстанавливаются из базы после перезапуска сервера.

## 7. Тревоги и уведомления (backend-core)

- `server/alarms/`: `raise(club_id, {type, level: "critical"|"important"|"info", resource_id?, data})` пишет `alarms` и журнал `alarm.raised`, уведомляет владельцев и управляющих клуба по их каналам. Уровни — PRODUCT §8.
- `server/notify/`: `send(user_id, {kind, text, data})` по цепочке каналов пользователя. Каналы: `webpush` (VAPID, ключи в `.env`), `max` и `telegram` — адаптеры по документации, до её доступности — `notify_skipped` в лог и запись в `notifications` со статусом `skipped`.
- Владелец видит тревоги в программе клуба независимо от доставки.

## 9. Прошивка v1 и симулятор (firmware)

- `firmware/`: `platformio.ini` (окружения `esp32dev` и `native`), драйверы, логика на чистом C++ в `firmware/lib/logic/`, NVS, TLS с закреплённым CA, Wi-Fi, точка доступа привязки, вызов `POST /api/devices/claim`, watchdog, OTA с откатом.
- Логика проверяется нативно: `pio test -e native` и, в этой среде, CMake + g++ (`firmware/test/native/`). Зависимости, которые нельзя скачать здесь, вендорятся в репозиторий с лицензиями.
- **Общие сценарии:** `tools/device-sim/scenarios/*.json` — последовательность команд, сдвигов времени, перезагрузок, обрывов связи и ожидаемых состояний. Их прогоняют и нативные тесты прошивки, и тесты симулятора. Расхождение — дефект.
- Симулятор: полный автомат протокола §5, сигналы, правило 4, режимы сбоя (флаги CLI и управляющий топик `sim/{device_id}/control` только в разработке, либо HTTP-управление на `127.0.0.1`), метрика времени `cmd` → `relay: true`.

## 10. Интерфейсы (frontend)

### Гость (`web/guest/`, `/app/`)
Экраны: «Стол» по `/app/t/{code}` (статус, цены сейчас и дальше, выбор 1/2/3 ч или «Без лимита»), вход (кнопки «Войти через MAX», «Войти через Telegram»; в разработке — по телефону), согласие отдельным флажком, оплата (переход на подтверждение ЮKassa или «Оплачу на ресепшене»), ожидание света, «Игра» (таймер на полэкрана, «Продлить», «Закончить игру», кто за столом), «Я играю за этим столом», чек, «Занят до 21:40», выбор после `interrupted`. Бар скрыт до M2.
Бюджет: < 200 КБ JS (gzip) на первую загрузку.

### Программа клуба (`web/admin/`, `/club/`)
- Ресепшн (планшет, горизонтально, без мыши): очередь заявок «Стол 4 · 2 ч · 1 600 ₽» со звуком, «Принять оплату» (наличные со сдачей, карта через терминал), зал с «Сервисный свет» (причина обязательна).
- Владелец и управляющий (телефон): «Сейчас» (тревоги сверху, зал, выручка за сегодня), журнал с фильтрами и «Проверить цепочку», тревоги, скачать QR-наклейки.

## 11. Окружение (devops)

- Caddy: `/api/*` → `server`, `/t/*` → `server` (перенаправление на `/app/t/{code}`), `/app/*` → `web/guest`, `/club/*` → `web/admin`, `/` → `/app/`. Заголовки безопасности и CSP без внешних источников.
- Сервис `yookassa-emu` в Compose разработки; `YOOKASSA_API_URL` на него.
- `.env`: `PUBLIC_HOST`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `ALLOW_DEV_LOGIN`, `YOOKASSA_API_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_PROXY_URL`, `MAX_BOT_TOKEN` — генерация и пустые значения по правилам M0.
- CI: сборка обоих приложений, проверка бюджета JS гостя, нативные тесты прошивки, `pio run` в отдельной задаче CI.
