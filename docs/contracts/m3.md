# Контракты M3 «Бронь и уведомления»

Автор: оркестратор. Зафиксирован 22.10.2026 после закрытия M2 (решения №104–112). Отклонение — только через оркестратора.

Цель M3 (ROADMAP): бронь с выбором стола на плане зала, предоплата, удержание, сгорание, старт по брони через QR; лист ожидания; ограничение продления перед бронью; цепочка уведомлений (основной канал, запасной при недоставке; MAX, Telegram через прокси, Web Push); утренняя сводка и сводка смены владельцу. Сценарии T18–T21. Плюс перенесённое: управление персоналом (№99), пакеты часов и депозит наличными для «Без лимита» (№87), второй чек при предоплате брони (№52).

Ограничения среды прежние: ЮKassa, MAX и Telegram проверяются на эмуляторах и заглушках; в отчёте — «проверено на эмуляторе».

## 1. Решения M3

1. **Бронь — отдельный модуль `server/bookings/`.** Свет и сессии по-прежнему только у light: старт по брони идёт через функцию light.
2. **Бронь держит интервал целиком:** пересечения броней одного стола запрещены ограничением базы (`exclude using gist` по `tstzrange`), гонки — блокировкой строки ресурса, как удержание в M1.
3. **Продление перед бронью ограничено** началом брони минус 5 минут: котировка продления возвращает `extend_limit_until` и не даёт купить больше (`booking_conflict`); гость видит «Стол забронирован на 21:00, можно продлить до 20:55».
4. **Удержание брони:** без предоплаты — 15 минут после начала, с предоплатой — 30 (PRODUCT §6). За 15 минут до начала стол получает `state.reserved` (синий), если свободен; если занят — бронь ждёт освобождения, а продление занятого ограничено (п. 3).
5. **Предоплата брони — чек предоплаты при оплате** (`full_prepayment`/`prepayment`), **при старте игры — чек зачёта предоплаты** (`full_payment` с зачётом) через ЮKassa; при сгорании — по правилам клуба: удержать или вернуть долю (настройка `booking_forfeit_percent`, по умолчанию 100 % — удержать). Проверить с бухгалтером пилотного клуба.
6. **Лист ожидания:** первый в очереди получает предложение на 5 минут (уведомление + SSE); не ответил — следующему.
7. **Цепочка уведомлений:** каналы пользователя в порядке предпочтения; недоставка (ошибка или нет подтверждения доставки за 30 с для мессенджеров) → следующий канал; итог и попытки — в `notifications`. Telegram — только через прокси. MAX — адаптер по документации, когда она станет доступна; до этого — заглушка с той же формой.
8. **Утренняя сводка** в 10:00 по времени клуба за вчерашние рабочие сутки (№43): выручка по способам, часы игры, загрузка, тревоги, ручные действия, хеш головы журнала (№13).
9. **Персонал:** владелец приглашает по телефону с ролью; приглашение действует 7 дней и привязывается при первом входе с этим номером; отзыв доступа — в один шаг, сразу гасит токены и PIN сотрудника; всё — в журнал.
10. **Пакеты часов:** клуб продаёт «N часов за X ₽ на M дней»; часы на балансе гостя (`balance_minutes`) в клубе; оплата игры балансом — способ `balance` (PRODUCT §19), без чека в момент списания (чек был при покупке пакета, `full_prepayment`, зачёт при списании — по №5 тем же механизмом).
11. **Депозит наличными для «Без лимита»** (№87): ресепшн принимает депозит в смене, сессия идёт до исчерпания по тарифу, при закрытии — расчёт по факту и возврат остатка наличными из кассы с чеком возврата; «Без лимита» по депозиту не продлевается сам.

## 3. Межмодульные интерфейсы

| Модуль | Функция или событие |
|---|---|
| `server/bookings/api.mjs` | `nextBookingStart(db, { resourceId, after })` → `Date` или `null`; `bookingForArrival(db, { resourceId, userId, at })` → бронь, которую можно начать; `markStarted(db, { bookingId, sessionId })` |
| `server/sessions/api.mjs` (light) | `startFromBooking(db, { booking, userId, paidMinutes, paymentIds })` → `session_id` (команда свету — как при оплате); `setReserved(db, { resourceId, until })` и `clearReserved(db, { resourceId })` (индикатор `state.reserved`) |
| `server/payments/api.mjs` (money) | `createPrepayment(db, { clubId, bookingId, amountKopecks, customer, ... })`; `settlePrepayment(db, { paymentId, sessionId })` — чек зачёта; `forfeitPrepayment(db, { paymentId, percent, reason })`; `debitBalance(db, { userId, clubId, minutes, sessionId })`; `takeDeposit(db, { clubId, sessionId, amountKopecks, staffId })`; `settleDeposit(db, { sessionId, usedKopecks })` → возврат остатка |
| outbox (booking) | `booking.created`, `booking.confirmed`, `booking.reserved`, `booking.started`, `booking.expired`, `booking.canceled`; `waitlist.offered`, `waitlist.accepted` |
| outbox (light, уже есть) | `session.closed` — на него подписан лист ожидания (стол освободился) |
| `server/notify/index.mjs` (core) | `send(db, userId, { kind, text, data, actions? })` — теперь с цепочкой каналов и возвратом `{ notification_id }`; статус доставки — в `notifications` |

Котировка продления (money, M1) вызывает `nextBookingStart` и ограничивает минуты.

## 4. API (основное)

| Метод и путь | Кто | Назначение |
|---|---|---|
| `GET /api/clubs/{club}/availability?date=` | без входа | свободные интервалы столов по дню (для плана зала и борт-шкалы) |
| `POST /api/bookings` | гость | `{resource_id, starts_at, minutes}` → бронь (`pending_payment` при предоплате, иначе `confirmed`) |
| `POST /api/bookings/{id}/pay` | гость, `Idempotency-Key` | предоплата (redirect ЮKassa) |
| `POST /api/bookings/{id}/cancel` | гость (свою), управляющий | отмена по правилам клуба (возврат предоплаты по правилам) |
| `POST /api/bookings/{id}/start` | гость-владелец брони у стола | старт по брони (QR); ранний приход при свободном столе — с доплатой |
| `GET /api/me/bookings`, `GET /api/clubs/{club}/bookings?date=` | гость / персонал | списки |
| `POST /api/clubs/{club}/bookings` | ресепшн и выше | бронь по телефону: имя, телефон (маска в ответе), источник `phone` |
| `POST /api/waitlist` / `DELETE /api/waitlist/{id}` / `POST /api/waitlist/{id}/accept` | гость | лист ожидания |
| `GET/POST/DELETE /api/clubs/{club}/staff…` | владелец | персонал: пригласить, роль, отозвать |
| `GET/POST /api/clubs/{club}/packages`, `POST /api/packages/{id}/buy` | управляющий / гость | пакеты часов |
| `POST /api/reception/deposits` | ресепшн | депозит наличными для «Без лимита» |
| `PATCH /api/me {notify_channel, channels_order}` | гость | каналы уведомлений |

## 5. Сценарии и приёмка

T18 бронь с предоплатой, гость не пришёл → удержание 30 мин, бронь сгорает, предоплата по правилам клуба. T19 гость перед бронью продлевает через время брони → продление ограничено «до 20:55». T20 стол освободился, есть очередь → первый получает предложение на 5 минут. T21 MAX-бот не доставил напоминание → ушло в запасной канал. Плюс: старт по брони через QR без повторной оплаты, чек зачёта предоплаты; пакет часов куплен и списан; депозит наличными: игра, возврат остатка, смена сходится; персонал: пригласить, войти, отозвать — токены и PIN погашены; утренняя сводка в 10:00 по поясу клуба.
