# Чек-лист пилота «Бильярдума»

Пилот — один клуб, 4–8 столов, монтаж электриком клуба, 2 недели (ROADMAP «Пилот»). Порядок работ на сервере — [`RUNBOOK.md`](RUNBOOK.md).

**Кто делает:**

- **А** — Андрей;
- **К** — клуб: владелец, управляющий или электрик;
- **D** — devops;
- **F** — firmware;
- **B** — backend;
- **T** — tester.

Пункт с пометкой **«да» Андрея** не начинается без его явного согласия в сообщении.

## 1. Сервер

- [ ] **А** Выбрать хостинг. ЦОД в РФ подтверждён **договором и документами** (адрес ЦОД), а не названием тарифа. Хостинг подписывает поручение на обработку ПДн. *«да» Андрея.*
- [ ] **А** Хранилище S3 для бэкапов у другого провайдера в РФ: бакет, ключ только на запись и чтение, правило хранения 35 дней.
- [ ] **А** Прокси для `api.telegram.org` (HTTP CONNECT или SOCKS5): адрес и логин в `TELEGRAM_PROXY_URL`.
- [ ] **А** По желанию — второй маленький сервер в РФ для внешнего монитора (RUNBOOK §6.4).
- [ ] **D** Ubuntu 24.04, Docker с `live-restore` и без `userland-proxy`, межсетевой экран: 22 — только администратору, 443 и 8883 — всем (RUNBOOK §4.1).
- [ ] **D** `gen-env.sh`, заполнить `prod.env`, затем `preflight.sh` без ошибок (RUNBOOK §4.3).
- [ ] **А** Ключ age Андрея (`age-keygen`): закрытый — офлайн, открытый — devops в `BACKUP_AGE_RECIPIENTS` и `BACKUP_ENV_AGE_RECIPIENT`.
- [ ] **А + D** CA платформы и сертификат брокера на ноутбуке Андрея (`mqtt-certs.sh`). `ca.key` остаётся у Андрея, на сервер идут `ca.crt`, `mqtt.crt`, `mqtt.key` (RUNBOOK §4.4).
- [ ] **D** Первая установка (RUNBOOK §4.5–4.8). *«да» Андрея.* После неё — таймеры, первый бэкап, `monitor.sh --dry-run` без критичных проблем.
- [ ] **D** Ручная проверка восстановления сразу после первого бэкапа: `restore-check.sh`, отчёт пришёл Андрею.
- [ ] **D + А** Окно обслуживания `MAINTENANCE_WINDOW` сверено с часами работы пилотного клуба.

## 3. Магазин ЮKassa клуба

Деньги гостей идут клубу, в его магазин. Ключи вводит владелец в мастере, на сервер их никто не пересылает.

- [ ] **К** Договор клуба с ЮKassa. Два магазина: **тестовый** и **боевой** (№154).
- [ ] **К** В боевом магазине включены СБП и карта, **фискализация (чеки 54‑ФЗ)** включена: «Чеки от ЮKassa» или своя онлайн-касса. Без неё мастер ответит `fiscalization_off`.
- [ ] **К** В обоих магазинах: HTTP-уведомления на адрес из мастера `https://{домен}/api/webhooks/yookassa/{club_id}`, события `payment.succeeded`, `payment.waiting_for_capture`, `payment.canceled`, `refund.succeeded`.
- [ ] **К** В мастере введены `shop_id` и секретный ключ обоих магазинов. Проверка `GET /v3/me` прошла: тестовый — `test`, боевой — `live` с чеками.
- [ ] **К** «Проверочный платёж 1 ₽» в тестовом магазине прошёл, вебхук пришёл (нет тревоги «вебхук ЮKassa не настроен»).
- [ ] **D** Адреса ЮKassa для вебхуков (`YOOKASSA_WEBHOOK_IPS`) сверены с документацией ЮKassa.

## 5. Контроллеры: сборка, прошивка, заводской реестр

- [ ] **А** Решение по железу (PRODUCT §22.1): своя плата или готовое Wi-Fi-реле. Заказ комплектов на 4–8 столов и один запасной.
- [ ] **F** `firmware/src/certs.local.h` прода:
  - `kMqttCaPem` — `ca.crt` платформы (§1);
  - `kApiCaPem` — корни Let's Encrypt **ISRG Root X1 и ISRG Root X2** обоими сертификатами: цепочка Caddy может смениться между RSA и ECDSA;
  - `kOtaPubKeyPem` — ключ подписи образов.
- [ ] **F** Сборка `pio run -e esp32dev` с `BL_API_URL=https://{домен}` и `BL_FW_VERSION`. Образ подписан, `sha256` записан.
- [ ] **D** Заводской реестр на сервере: `provision-factory --count N --batch P-…` (RUNBOOK §4.6). PDF и команды — на машину сборки, на сервере стереть. *«да» Андрея.*
- [ ] **F** Каждому контроллеру по USB: прошивка и команда `factory BLD1:…` (ответ `factory_saved`). Наклейка с QR — на корпус.
- [ ] **F + T** На стенде: контроллер с прод-прошивкой видит точку доступа, проходит claim через тестовый клуб на проде и подключается к `mqtt.{домен}:8883`.

## 6. Монтаж электриком клуба

- [ ] **К** Электрик клуба ставит контроллер в разрыв линии 220 В света стола по инструкции из комплекта: автомат, корпус. Ответственность клуба (PRODUCT §18). Монтаж — при выключенном автомате, по одному столу.
- [ ] **К** Wi-Fi клуба на 2,4 ГГц у каждого стола уверенный (RSSI видно в программе клуба). Роутер клуба на ИБП — по возможности.
- [ ] **К** После монтажа: стол в программе на связи, сервисный свет из программы включает и гасит лампу (действие с причиной, уведомление владельцу).
- [ ] **К** Если в комплекте есть датчик тока: «свет в обход» срабатывает при включении лампы мимо контроллера.

- [ ] **К** Магазины ЮKassa (§3).
- [ ] **К** Контроллеры: сканер QR на корпусе → стол → Wi-Fi клуба на портале контроллера. Окно привязки — 30 минут.
- [ ] **К** Наклейки QR на столы: PDF A4, по наклейке на стол.

## 8. Тестовый режим

Свет работает по-настоящему, оплаты идут в тестовый магазин, касса печатает «ТЕСТ», записи помечены `is_test` (№153). Минимум 2–3 дня с персоналом клуба.

- [ ] **К + T** Гость сканирует QR → платит (тестовая карта или СБП) → свет загорается. Время «скан → свет» — меньше 30 с.
- [ ] **К + T** Сигналы конца игры: за 10, 5, 1 минуту. Продление из приложения. Свет гаснет по времени.
- [ ] **К + T** Сбой связи: роутер клуба выключен на 3 минуты посреди оплаченной игры. Игра доигрывается, не продлевается. Владелец получает тревогу офлайна. После включения стол сам на связи.
- [ ] **К + T** Сбой сервера: пока идёт игра, devops перезапускает `server` (не брокер). Игра продолжается, приложение снова работает через секунды.
- [ ] **К + T** Ресепшн: продажа бара, наличные и терминал, открытие и закрытие смены, нефискальный «ТЕСТ».
- [ ] **К + T** Бронь по QR и с ресепшена, старт игры по брони.
- [ ] **К** Ручные действия (сервисный свет, бесплатная игра, скидка выше лимита) требуют причины и уведомляют владельца.
- [ ] **D** Монитор за тестовые дни: нет критичных тревог, outbox и очереди чеков и уведомлений пустые, бэкапы каждый день.
- [ ] **А** Итоги тестового режима, решение о боевом. *«да» Андрея.*

## 9. Переход в боевой режим

- [ ] **А** Юридическое: уведомление Роскомнадзора подано (с адресом ЦОД), оферта и политика опубликованы (`docs/legal/`), версии `CLUB_OFFER_VERSION` и `CONSENT_VERSION` совпадают с текстами.
- [ ] **К** Чек-лист в программе клуба (№160):
  - столы в работе;
  - контроллеры на связи за 10 минут;
  - тарифы покрывают неделю;
  - боевой магазин с чеками;
  - мост ККТ на связи, ККТ фискальная;
  - наклейки напечатаны;
  - оферта принята.
- [ ] **К** «Перейти в боевой режим». Андрей получает уведомление, карточка клуба в каталоге связывается с клубом.
- [ ] **К** «Проверочный платёж 1 ₽» в боевом магазине с автоматическим возвратом. Чек ЮKassa пришёл.
- [ ] **К** Первая боевая продажа на кассе — фискальный чек с ФД и ФП в программе клуба.
- [ ] **D** Первые сутки в боевом режиме: devops смотрит монитор и логи (`compose.sh logs --since 1h server`), Андрей получает утреннюю сводку клуба.

## 10. Метрики пилота и еженедельный отчёт

Цели — PRODUCT §21:

| Метрика | Цель | Где смотреть |
|---|---|---|
| Доля игр, запущенных без персонала | 80 % и выше | дашборд владельца (M5.2), отчёт по понедельникам |
| Игр со светом без записи в журнале | 0 | там же; любая — разбор с backend в тот же день |
| Расхождение кассы на закрытии смены | 0 ₽ или объяснено в журнале | отчёт смены, отчёт по понедельникам |
| Время от скана QR до света | медиана меньше 20 с | дашборд, отчёт по понедельникам |
| Доля продлений из приложения | растёт | дашборд, отчёт по понедельникам |

- [ ] **D** `billiardum-pilot-report.timer` включён. Отчёт приходит Андрею по понедельникам в 09:07 (RUNBOOK §6.3). Вручную: `pilot-report.sh --print`.
- [ ] **А** Каждую неделю — короткий разбор с клубом: что мешало играть без персонала, жалобы гостей, тревоги.
- [ ] **D** Каждую неделю: доля контроллеров онлайн, тревоги монитора за неделю, бэкапы и проверка восстановления (первый вторник месяца).
- [ ] **А** Итог пилота через 2 недели: метрики против целей, решение о следующих клубах.

## 11. Обновления во время пилота

- [ ] Выпуск сервера — только с «да» Андрея, утром, с готовым откатом (RUNBOOK §5).
- [ ] Прошивка — только с «да» Андрея: сначала один свободный стол, проверка игры на нём, затем остальные по одному, только свободные (протокол §8).
- [ ] Брокер и база — без перезапусков в часы работы клуба (RUNBOOK §5.5).
