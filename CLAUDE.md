# Бильярдум

Платформа для бильярдных клубов России по модели LANGAME: программа клуба, контроллер света на каждом столе, приложение гостя (PWA и мини-приложения MAX и Telegram), публичный сайт-агрегатор с турнирами и рейтингом игроков. Владелец проекта: Андрей.

Что строим подробно: `docs/PRODUCT.md`. Протокол контроллера: `docs/protocol.md`. Дизайн: `docs/DESIGN.md`. Этапы и тесты: `docs/ROADMAP.md`. Принятые решения: `docs/decisions.md`.

## Цель релиза

Клуб работает с минимальным участием персонала. Стандартная игра проходит без единого действия сотрудника: гость сканирует QR на столе, платит, свет включается, система сама предупреждает о конце времени, продлевает по оплате и гасит свет. Ресепшн продаёт бар и принимает наличные и карты, как кассир в магазине.

## Инварианты (нарушение — блокер)

1. Свет над столом включает только сервер подписанной командой контроллеру. У каждой команды есть запись в журнале.
2. Журнал действий только дополняется. UPDATE и DELETE запрещены всем ролям (RLS и триггер). Записи связаны хешами в цепочку.
3. Оплаченная игра не обрывается из-за сбоя связи или сервера: контроллер доигрывает оплаченное время сам.
4. Неоплаченная игра не продолжается: контроллер никогда не продлевает время сам.
5. Каждый клуб видит только свои данные: RLS по `club_id` на всех таблицах.
6. Данные гостей хранятся только на серверах в РФ (152‑ФЗ).
7. Каждый приём денег даёт чек по 54‑ФЗ: онлайн через ЮKassa, на ресепшене через ККТ клуба.
8. Ручное действие персонала (сервисный свет, бесплатная игра, скидка выше лимита, отмена, возврат, продление без оплаты, изменение тарифа, удаление из чека) требует причины и сразу уходит владельцу уведомлением.
9. Клиент не ходит в базу напрямую и не шлёт команды контроллеру. Только через `api/`; сервер проверяет права и оплату.
10. Деньги храним целыми копейками. Время в базе в UTC. У клуба свой часовой пояс (IANA), тарифные интервалы считаются по местному времени клуба.

## Стек

- Сервер: Node 22, ESM, обработчики `(req, res)`, вход `server/index.mjs`.
- База: self-hosted Supabase (Postgres и RLS) на сервере в РФ. Сервисы Supabase наружу не публикуются, `api/` ходит в Postgres через `pg` (decisions №11).
- Контроллер: ESP32, PlatformIO и Arduino (C++), MQTT по TLS через Mosquitto.
- Оплата: ЮKassa (СБП, карта, чеки). У каждого клуба свой магазин, деньги гостей идут клубу.
- Касса на ресепшене: ККТ клуба через `tools/kkt-bridge/` (сначала АТОЛ).
- Уведомления: MAX-бот (основной), Telegram-бот (только через прокси: с сервера закрыт `api.telegram.org`), Web Push.
- TLS и прокси: Caddy.
- Веб: `web/guest/` (PWA и мини-приложения), `web/admin/` (владелец, управляющий, ресепшн, экран бара, ТВ-экраны), `web/site/` (публичный сайт с серверным рендером для SEO). Шрифты и статика только со своего сервера.

## Соглашения

- Интерфейс и тексты на русском. Форматы ru-RU: «1 490 ₽», «21:30», «21 октября».
- Склонение числительных одной функцией `plural(n, ['стол', 'стола', 'столов'])`.
- Ошибки API наружу только кодом: `{"error":"table_busy"}`. Подробности в логе сервера.
- Идентификаторы UUID.
- Операции с деньгами идемпотентны: ключ идемпотентности на каждый запрос к ЮKassa, вебхук обрабатывается один раз по `payment_id`.
- В логах нет персональных данных: телефоны маскируются.
- Демо-данные только в сиде для разработки. В проде пустые состояния, без выдуманных клубов, отзывов и цифр.
- Секреты только в `.env`. В репозиторий не коммитятся, в чат не выводятся (только длина).
- Код ресурса универсальный: в модели и API «resource», в интерфейсе бильярда «стол».

## Готово, когда

- Логика покрыта тестами: тарифы, сессии, журнал, протокол, деньги.
- tester прошёл сценарии этапа из `docs/ROADMAP.md`, включая симулятор.
- pentester проверил изменения, если затронуты деньги, вход, данные гостей, протокол, журнал или свет.
- Обновлены `docs/protocol.md`, `docs/decisions.md` и README модуля.

## Нельзя

- Деплоить в прод и обновлять прошивки в клубе без явного «да» Андрея.
- Перезапускать Mosquitto в часы работы клубов.
- Парсить 2ГИС, Яндекс Карты и другие справочники для наполнения каталога.
- Подключать пиксели Meta и сервисы, которые передают данные гостей за рубеж.
- Показывать алкоголь в QR-меню до заключения юриста.
