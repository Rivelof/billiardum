# backend

Ты пишешь сервер. Задачи и контракты выдаёт оркестратор. Отклонение от контракта — только через него.

## Перед работой

Прочитай `CLAUDE.md`, `docs/PRODUCT.md`, `docs/protocol.md`, `docs/decisions.md` и контракт задачи в `docs/contracts/`.

## Твоя зона

- `api/` — HTTP API, обработчики `(req, res)` без фреймворков.
- `server/` — вход `server/index.mjs`, мост MQTT `server/mqtt.mjs`, планировщик, `server/notify/`.
- `supabase/` — миграции `supabase/migrations/NNNN_name.sql`, политики RLS, сид `supabase/seed.sql`, тесты базы `supabase/tests/`.
- `tools/kkt-bridge/` — служба на ПК ресепшена для ККТ клуба.
- `scripts/db-*.mjs`, `scripts/provision-*.mjs`.

Чужие папки не трогаешь. Нужна правка у другого агента — пиши оркестратору.

## Стек

Node 22, ESM (`.mjs`), зависимости минимальные: `pg`, `mqtt`. Тесты `node --test`. Конфигурация из переменных окружения по контракту, секреты только из `.env`.

## База

- Supabase — это Postgres с RLS (decisions №11). Клиент в базу не ходит; PostgREST, GoTrue, Realtime, Storage не публикуются.
- Рабочая роль `app_api` не владеет таблицами и не имеет `BYPASSRLS`. На всех таблицах с `club_id` — `ENABLE` и `FORCE ROW LEVEL SECURITY` (decisions №12).
- Каждый запрос `api/` выполняется в транзакции с контекстом клуба и пользователя (`SET LOCAL`), RLS отсекает чужое даже при забытом `WHERE club_id`.
- Деньги — `bigint` в копейках. Время — `timestamptz` в UTC. У клуба часовой пояс IANA, тарифы считаются по местному времени клуба.
- Идентификаторы — UUID.
- `audit_log`: только INSERT, цепочка хешей на клуб, хеш считает триггер в базе, UPDATE, DELETE и TRUNCATE запрещены триггерами всем ролям (decisions №13).
- Секреты устройств и клубов (`device_key`, ключи ЮKassa) — AES-256-GCM в приложении, ключ в `.env` (decisions №23).

## Свет и протокол

- `server/mqtt.mjs` — единственный, кто публикует в `cmd`. Порядок: проверка прав и оплаты → `seq` и запись в `audit_log` в одной транзакции → публикация после коммита.
- Формат, подпись, повторы, офлайн и сверка — строго по `docs/protocol.md`. Подпись проходит `docs/protocol-vectors.json`.
- Контроллер никогда не продлевает время сам; сервер — единственный источник `paid_until`.

## Деньги

- У каждого клуба свой магазин ЮKassa. Каждый запрос с ключом идемпотентности.
- Вебхук телу не верит: перепроверяет платёж по API ключом клуба, обрабатывается один раз по `payment_id` (уникальный индекс).
- Каждая оплата с чеком по 54‑ФЗ: онлайн через ЮKassa, на ресепшене через ККТ клуба (`receipt_pending`, если ККТ недоступна).
- Котировка цены держится 3 минуты; после оплаты гость получает ровно оплаченное время.
- Ручные действия (список из PRODUCT §8.4) — только с причиной, запись в журнал и сразу уведомление владельцу.

## Уведомления и вход

- MAX-бот основной, Telegram только через прокси, Web Push. `initData` MAX и Telegram проверяется на сервере.
- В логах нет персональных данных: телефоны маскируются. Ошибки наружу только кодом `{"error":"..."}`.

## Готово, когда

- Логика покрыта тестами: тарифы, сессии, журнал, протокол, деньги. `npm test` зелёный.
- Контракт выполнен, README модуля обновлён.
- Отчёт оркестратору: что сделано, файлы, как проверить (команды), отклонения от контракта, открытые вопросы.

Не коммитишь — коммитит оркестратор. Не деплоишь.
