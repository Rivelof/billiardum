## M5.2 — выдержало

- **Изоляция:** владелец B против клуба A — 403 во всех маршрутах; подмена `?club=` и `X-Club-Id` не работает (`api/router.mjs:350`); `club=all` — только клубы, где пользователь владелец или управляющий (`server/dashboard/scope.mjs:7`); чужой стол или статья — 404; кэш 60 с — ключи по клубу и по пользователю для `all`, утечки нет.
- **Роли:** ресепшн и бар — 403; управляющий без экспорта, без счетов подписки, без справочника статей; подписка для управляющего — только состояние.
- **ПДн:** дашборд — только количества; истории и «Кто играл» — ник или маска; полный телефон — только владельцу через `bl.guest_phone` (1102), без причины 400, журнал `guest.lookup` без номера, тревога `manual_action` владельцу при каждом вызове; лимит 20/мин.
- **Касса:** суммы ≤ 0, дробные, > 1 млрд — 400; только INSERT (триггер); двойное сторно — 409; сторно сторно — 400; чужой клуб — 404.
- **CSV:** формулы Excel нейтрализуются апострофом (`server/dashboard/csv.mjs:cell`), все выгрузки через `toCsv`.
- **Агрегаты:** `stats_put_day` — только `actor_type=system` и клуб из контекста; `app_api` — только чтение.
- **Период и DoS:** > 366 дней — 400; `club=all` × 366 дней — ~50 мс; кэш и лимит 60/мин.
- **Журнал:** новые записи — только серверным `appendAudit`; инвариант 2 не затронут.

## M5.3 — выдержало

- **Вебхук платформы:** телу не верят — только `object.id`, перепроверка в магазине платформы, сверка `metadata`, суммы, магазина, статуса (`server/billing/core.mjs:applyRemote`); подделки — no-op; двойной вебхук и двойная оплата — счёт закрывается один раз.
- **Разделение денег:** платёж гостя на адрес платформы и наоборот отсекается магазинами; магазин клуба ≠ магазин платформы (`server/clubs/shops.mjs:126`).
- **Клуб не меняет себе цену, `paid_until`, пробный период:** у `app_api` нет прав на эти колонки, запись — только в контексте платформы.
- **Ручки платформы:** `mark-paid`, `price`, `plans` — только `platform_admin`, с причиной.
- **`return_url`:** только свои адреса — открытого редиректа нет. Секрет магазина в ответы и логи не попадает.

## Наблюдения (низкая важность)

1. **Нет явного `club_id` в узких чтениях** (`api/routes/who-played.mjs:33, 92`, `server/dashboard/cashbook.mjs` addEntry) — держит только RLS. Добавить `and club_id = bl.ctx_club_id()` вторым рубежом. Владелец — backend.
2. **Касса: запись можно датировать любой прошлой датой** (`addEntry` проверяет только «не в будущем»), рутинные записи не уведомляют владельца; датировка в закрытый период меняет историческую прибыль. Решение — №189.
