## Часть 1: ключи и изоляция — выдержало

1. **Изоляция:** ключ клуба A на всех пяти маршрутах отдаёт только A; `X-Club-Id`, `?club=`, `?club_id=`, cookie владельца B игнорируются; клуб — только из ключа (`auth.mjs:82, 92`), в `read.mjs` явный `club_id = $1` поверх RLS.
2. **Ключ и вход разделены:** ключ на маршрутах персонала, `/api/me`, в cookie или `?api_key=` — 401; сессия владельца на `/api/v1/club/*` — 401 (`router.mjs:335`).
3. **Неверный и отозванный ключ** — 401 сразу; чужой ключ отозвать нельзя; сравнение через HMAC-SHA256 с перцем по индексу (`keys.mjs:46`) — по времени ничего не выдаёт.
4. **Только GET:** другие методы — 405; ключ на других маршрутах — 401; правило «`/api/v1/club/` ⇔ `auth 'api_key'` ⇔ GET» проверяется при сборке маршрутов (`router.mjs:126–128`); транзакция READ ONLY (`auth.mjs:47`).
5. **Права:** без права — 403 `scope_required`; пустой или неизвестный список при выпуске — 400.
6. **ПДн:** в `tables`, `tariffs`, `availability`, `sales`, `bookings` нет телефонов, имён, `user_id`, `session_id`, `payment_id`, `created_by` (проверено на брони с именем и телефоном).
7. **Лимит 5 ключей:** из 7 параллельных выпусков — 5 × 201, 2 × 409.
8. **Выпуск — только личным входом:** по PIN — 403; управляющему и чужому владельцу — 403; хеш ключа `app_api` не читает.
9. **Журнал:** `api_key.*` без ключа и хеша (только префикс); `audit/verify` — 200; заголовок `Authorization` не логируется.

### Находка (низкая)

- **Кривой курсор в `/bookings` — 500 вместо 400.** `server/clubapi/read.mjs:220` проверяет второй элемент курсора регуляркой `/^[0-9a-f-]{36}$/`; 36 дефисов проходят и падают на `$7::uuid` (22P02). Наружу — только код. Исправление — `isUuid`. Владелец — backend.

### Решение

Отзыв ключа по PIN владельца оставлен (решение оркестратора): отзыв только убирает доступ.

Ключ клуба в `suspended` и лимиты 600/60 — по коду; запись внутри READ ONLY — по коду; таблицы с живой игрой и реальными оплатами в своих клубах — по коду. Вебхуки — часть 2.
