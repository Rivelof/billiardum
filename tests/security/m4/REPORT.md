## Находки

### M4-2 (средняя, инвариант 4)

`server/tournaments/service.mjs` `step` (~1466–1480) каждые 15 с вызывает `light.extendFromTournament(until = now + max(15, match_minutes/2))`, пока матч `playing`, `pending_confirm` или `disputed`. `server/sessions/service.mjs` `extendFromTournament` (~1100–1130) принимает любой срок до 24 ч. Предела по `ends_at` и тревоги нет. Счёт не вносят, вносит один или вносят разный — стол горит бесплатно, пока организатор не вмешается. PoC `tournament_light.test.mjs`: через 30 ч после конца турнира 75 продлений, свет горит, тревог нет.

Исправление: продлевать только `playing` и не дальше `ends_at` + `match_minutes`; после внесения счёта — гасить или короткий фиксированный интервал; тревога «матч затянулся» организатору и владельцу.

### M4-3 (низкая)

`confirm` (~1222–1232) берёт текущий счёт соперника из базы, тело не читает; `report` (~1178) разрешает переписать свой счёт в `pending_confirm`. A вносит 1:2, B видит, A меняет на 2:1, B подтверждает — победа A без спора. PoC `tournament_attacks.test.mjs`, первый тест. Исправление: `confirm` с ожидаемым счётом и 409 при расхождении, либо запрет переписывать.

### M4-4 (низкая, данные гостей)

`server/directory/listings.mjs` `patchPlatform` (~228–233): при одобрении заявки «Подтвердить клуб» статус карточки не перепроверяется, `contact_user_id` безусловно становится заявителем; `already_claimed` проверяется только при подаче. Старая заявка злоумышленника, одобренная после настоящего владельца, — 200, заявки гостей с телефоном уходят ему. PoC `directory_attacks.test.mjs`, первый тест. Исправление: одобрять только пока карточка `listed`, иначе 409 `already_claimed`; при одобрении отклонять остальные открытые заявки на карточку.

### M4-5 (низкая)

`server/notify/index.mjs` `NUMBER_RUN` не учитывает разделители `.` и `/`; публикация — `server/directory/reviews.mjs` `upsert` (~58). `+7.912.345.67.81` и `8/912/345/67/82` публикуются как есть. PoC `directory_attacks.test.mjs`. Исправление: между цифрами пропускать любые короткие (1–2 символа) нецифровые разделители.

### M4-6 (низкая, доступность)

`api/router.mjs` (~266–271): запросы из `PUBLIC_API_TRUSTED_CIDRS` без лимита; у `web/site/server.mjs` лимита нет, кэш по пути — каждый новый адрес клуба идёт в API и базу. PoC `live_stand.test.mjs`: 130 разных адресов за 2 с — все 404, ни одного 429/503 (напрямую в API 121-й — 429). Исправление: лимит на сайте по IP гостя.

### M4-7 (низкая, доступность)

`server/http/sse.mjs` `attach` (~54–62): общий предел 2000 на всех; `publicStream` и ТВ-экран (`server/tournaments/tv.mjs`) — по 10 с IP, без входа и без проверки турнира. PoC `sse_public.test.mjs`: 200 IPv6 из одной /64 занимают хаб, ресепшн и гость получают `too_many_clients`. Исправление: отдельный предел анонимных потоков с запасом для вошедших, лимит на /64, поток только для существующего опубликованного турнира.

## Замечания

- **M4-I1.** Котировка QR на столе турнира — `409 table_busy` без `reason: 'tournament'`: `MoneyError` теряет поле (`server/payments/`).
- **M4-I2.** Антиспам leads: `elapsed_ms` задаёт клиент; держит только лимит по IP (5 за 10 мин, 5 в сутки).
- **M4-I3.** Лимит T23 по паре: три свои учётки в одной сессии — 9 засчитанных партий в сутки (+138). №136 не нарушено; вопрос продукта — лимит на игрока или сессию.
- **M4-I4.** `TRUSTED_PROXY_CIDRS` по умолчанию — все частные сети (`deploy/dev/compose.yml:143`): контейнер в сети Docker напрямую на `server:3000` подставляет `X-Forwarded-For` сайта и снимает лимиты. Через Caddy не проходит. Доверять только Caddy и сайту.
- **M4-I5.** Решения организатора владельцу по-разному: исправление счёта — `info`, отмена турнира — `manual_action`, решение спора (`plus.match_resolve`) — никак. По инварианту 8 — `manual_action` для всех.

## Проверено и выдержало

- Деньги турнира: запись без оплаты не участвует; повторная запись — та же; двойная оплата — один возврат лишнего, и при повторе события; отмена до закрытия записи — один возврат; оплата после старта — возврат; возвраты идемпотентны и не больше оплаты, чек возврата с позициями продажи (чтением кода).
- Свет: только сервер, `session.start` и `device.cmd` в журнале; бронь в окне турнира и QR между матчами — 409; отмена турнира — с причиной, ресепшн и игрок 403, тревога владельцу, свет гаснет (стенд, стол 8).
- Исправление счёта — только владелец или управляющий своего клуба, с причиной, `manual.tournament_score`.
- Бильярдум+: чужую партию не подтвердить и не оспорить; истечение через 30 мин; T23 выдерживает гонку (из 4 параллельных — ровно 3); спор решает только управляющий клуба партии; приватность и «друзья в клубе»; `show_clubs` скрывает из таблиц; приглашения ≤ 10 в сутки; все SECURITY DEFINER схемы `bl` с `search_path`, закрыты для public; `asUser` восстанавливается.
- Заявки T25 и роли платформы: токен не подходит к чужой заявке, одноразовый, 24 ч, перебор — 429; ≤ 3 открытых заявок гостя; `/api/platform/*` — 403 гостю и владельцу клуба; `ctx_platform_role` не верит установке роли без записи в базе; клуб не меняет статус, видимость и контакт своей карточки (42501).
- Отзывы: только после игры; отвечает только свой клуб.
- Инвариант 5: все таблицы ENABLE и FORCE RLS; в 11 новых таблицах чужие строки не видны; вставка с чужим `club_id` — 42501.
- Инвариант 2: UPDATE и DELETE запрещены; `audit_verify` на стенде после атак — клуб ok (6129 записей), платформа ok.
- Публичный API и сайт: без ПДн; кэш общий (ответ с токеном = анонимный); поток турнира — только события сетки; SSR и JSON-LD экранируют XSS; OG-картинки экранированы и ограничены по длине; подделка `X-Forwarded-For` через Caddy и на сайте не помогает.
- Ошибки, логи, секреты: белый список полей держит; в логах за 6 ч нет телефонов; в отслеживаемых файлах нет секретов.
