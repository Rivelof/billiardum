# @billiardum/web-site — сайт-агрегатор

Публичный сайт «Бильярдума» (PRODUCT §15, контракт `docs/contracts/m4.md` §1 п.1–2, 13–15, решения №131, №140–142). Серверный рендер на Node 22 и Preact `renderToString` без фреймворка: страницы клубов, городов и турниров отдаются готовым HTML, интерактив — маленькие острова. В базу сайт не ходит: данные — только из публичного API сервера (`/api/public/*`), ответы кэшируются в памяти на 60 с. Владелец — frontend.

## Запуск

```sh
npm run build -w @billiardum/web-site     # острова → web/site/dist (esbuild)
npm run start -w @billiardum/web-site     # http://localhost:3100
npm run dev   -w @billiardum/web-site     # scripts/dev.mjs: пересборка островов и перезапуск сервера (заглушка API), Linux/macOS/Windows
npm run build:watch -w @billiardum/web-site   # только пересборка островов (её берёт корневой npm run dev)
npm run test  -w @billiardum/web-site     # node --test: маршруты, фильтры без JS, SEO, sitemap, 404, кэш, OG, бюджет JS
npm run size  -w @billiardum/web-site     # вес JS каждой страницы (бюджет 50 КБ gzip)
```

В Compose сервис `site` поднимает devops (`deploy/dev/compose.yml`), Caddy отдаёт ему всё, кроме `/api/`, `/app/`, `/club/`, `/t/`, `/pay/`.

## Переменные окружения

| Переменная | Что | По умолчанию |
|---|---|---|
| `PORT` | порт сервера сайта | `3100` |
| `BL_API_URL` | адрес API по внутренней сети, например `http://server-api:3000`; пусто или `mock` — заглушка `mock/` | заглушка |
| `SITE_ORIGIN` | публичный адрес для канонических ссылок, sitemap и OG | `http://localhost:{PORT}` |
| `YANDEX_METRIKA_ID` | номер счётчика Метрики (только цифры); пусто — счётчика нет | — |
| `YANDEX_VERIFICATION` | код Яндекс Вебмастера (`meta yandex-verification`) | — |
| `BL_SITE_NOINDEX` | `1` — стенд: `robots.txt` закрыт целиком, `noindex` | — |
| `BL_SITE_CACHE_MS` | время жизни кэша ответов API | `60000` |
| `OG_CACHE_DIR` | папка кэша OG-картинок на диске (кроме памяти) | только память |
| `BL_SITE_DEV` | `1` — лог запросов, CSS и манифест перечитываются на каждый запрос | — |
| `SITE_TRUSTED_PROXIES` | доверенные прокси (CIDR через запятую): только от них сайт верит `X-Forwarded-For`, иначе IP гостя — адрес сокета | `127.0.0.1/32,::1/128` |
| `BL_SITE_RATE_PER_MIN` | лимит походов в API на IP гостя в минуту (IPv6 — на /64); `0` — без лимита | `120` |

Страницы — с косой чертой на конце (без неё — 301). Отправка заявки без JS: `POST /dlya-klubov/zayavka/` → сайт передаёт в `POST /api/leads` с `X-Forwarded-For` гостя → 303 на `?zayavka=ok`; ошибка — та же страница с объяснением и введёнными данными. С JS (остров `forms`) — тот же адрес с `Accept: application/json`.

## Производительность и доступность (заглушка, локально, Lighthouse 13.5 мобильный)

| Страница | Performance | A11y | Best practices | SEO | LCP | CLS | TBT | Вес |
|---|---|---|---|---|---|---|---|---|
| `/` | 99 | 100 | 100 | 100 | 1,8 с | 0,002 | 0 мс | 132 КБ |
| `/ekaterinburg/` | 100 | 100 | 100 | 100 | 1,5–1,7 с | 0,002 | 0 мс | 101 КБ |
| `/ekaterinburg/svoyak/` | 99 | 100 | 100 | 100 | 1,8 с | 0,002 | 0 мс | 135 КБ |

CLS на реальных данных (Д6 приёмки M4): на стенде у города было 0,204 — абзац над каталогом переносился иначе, когда поздно доезжал латинский набор Geologica (цифры, пробелы, знаки препинания есть почти в каждом абзаце; браузер узнавал о нём только после первой раскладки). Теперь `geologica-latin` предзагружается вместе с кириллицей; кнопка «Показать клубы» (`[data-autosubmit-hide]`) скрыта стилем `.js [data-autosubmit-hide]` с первой отрисовки — класс `js` на `<html>` ставит встроенный скрипт темы. Локально сайт на данных стенда: город, клуб, главная — CLS 0, Performance 99–100. На медленной сети (150 мс, 1,6 Мбит/с) смена шрифта ещё может сдвинуть абзац, если кириллица и латиница приходят в разное время.

JS страницы (gzip, с чанками): главная 7,1 КБ (разбой ≈ 3 КБ), город 0,7 КБ, клуб 4,1 КБ, «Для клубов» 3,6 КБ. CSS инлайн ≈ 11 КБ gzip. Разбой считает физику только после первой прокрутки — загрузка страницы за неё не платит. axe-core 4.14 (WCAG 2.1 A/AA и best-practice): 0 нарушений на 15 адресах × 2 темы × 360 и 1280 px. Горизонтальной прокрутки страницы нет; прокручиваются внутри блока только сетка турнира, вкладки и широкие таблицы.

## Безопасность

- CSP с сайта: `script-src 'self'` + хеши встроенных скриптов (тема, Метрика), `style-src 'self'` + хеш встроенного CSS, без `unsafe-inline`; атрибутов `style` в разметке нет. `frame-ancestors 'none'`.
- Данные API в HTML экранирует Preact; JSON-LD экранирует `</`, U+2028, U+2029. Сырая разметка — только SVG из `shared/` и Markdown после экранирования.
- Внешние ссылки клуба (MAX, Telegram, сайт) — только `https://`, `rel="noopener nofollow"`.
- Лимит по IP гостя (M4-6): сайт ходит в API из доверенной сети без лимита API, поэтому ограничивает гостей сам — около 120 запросов в API в минуту с IP (`BL_SITE_RATE_PER_MIN`), IPv6 — по /64. IP — как для заявок: `X-Forwarded-For` только от `SITE_TRUSTED_PROXIES`. Статика, `/health`, страницы и 404 из кэша не считаются; одна страница — один жетон, сколько бы запросов в API она ни сделала. Превышение — 429 со страницей сайта («Слишком много запросов с вашего адреса»), `Retry-After` и `no-store`; форма заявки с JS получает JSON. 404 кэшируются: данные — 30 с, HTML — `public, max-age=30`.
- Метрика — только с `YANDEX_METRIKA_ID` (только цифры), `webvisor:false`, `clickmap:false`; иначе на сайте нет ни одного внешнего запроса.

## Открытые вопросы

- Тексту H1 нужен предложный падеж города: сайт склоняет сам (`cityIn`, словарь и правила); надёжнее — поле `name_in` в `GET /api/public/cities`.
- Турнир (`club: {id, name, city}`) не знает адреса страницы клуба и часового пояса: сайт строит индекс `club_id → path` из карточек клубов на программе (запрос на клуб раз в минуту). Нужны `club.path` (или `city_slug`, `slug`) и `club.timezone` в T. В `ClubSummary` пригодится `club_id`.
- В `GET /api/public/cities` нет «свободно сейчас» по городу — главная суммирует `free_now` клубов.
- Пути приложения гостя для «Добавить клуб» и «Подтвердить клуб» (`/app/directory/add`, `/app/directory/claim/{listing_id}`) — предложение; маршрутов в `web/guest` пока нет.
- План зала на сайте — сетка без координат (как `planLayout`): `live.tables[].plan {x, y, rotation}` пока не используются.
