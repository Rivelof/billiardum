# @billiardum/web-guest — приложение гостя

PWA по адресу `/app/` (Vite + Preact, JS ESM, без UI-библиотек — decisions №51). Экраны M1 по `docs/contracts/m1.md` §10, дизайн — `docs/DESIGN.md` («Свет над столом»): сверху всегда тёмный зал со столом и лампой, ниже — выбор и действия под большой палец.

## Запуск

```sh
npm run dev:mock -w web/guest     # заглушка API, без сервера: http://127.0.0.1:5173/app/
npm run dev -w web/guest          # настоящий API: прокси /api → BL_API_URL (по умолчанию http://127.0.0.1:3000)
npm run build -w web/guest        # dist/ для Caddy (/app/* → web/guest/dist); стенд разработки: VITE_DEV_LOGIN=1 — форма входа по телефону
npm run size -w web/guest         # сборка + бюджет < 200 КБ JS gzip на первую загрузку, нет заглушки и внешних адресов
npm test -w web/guest             # node --test: логика таймера, слова, вход, адреса, маршруты, заглушка
```

Сейчас первая загрузка — около 35 КБ JS gzip; бар — отдельный чанк (~6 КБ gzip), грузится при открытии.

## Экраны и маршруты

| Путь | Экран |
|---|---|
| `/app/` | текущие игры или «Отсканируйте QR-код на столе» |
| `/app/t/{code}` | «Стол»: номер, тип, статус словом, цена сейчас и дальше, 1/2/3 ч или «Без лимита»; шаги `?step=signin`, `consent`, `pay` на той же странице. Занятый стол — «Стол занят до 21:40» и «Я играю за этим столом» |
| `/app/wait/{payment_id}` | `return_url` ЮKassa: «Ждём подтверждения» → «Включаем свет…» до появления сессии → «Игра» |
| `/app/r/{request_id}` | «Оплачу на ресепшене»: что сказать администратору, срок заявки, отказ или сгорание |
| `/app/s/{id}` | «Игра»: таймер на полэкрана моноширинным, янтарный за 5 минут, красный в льготу (лампа приглушается), «Продлить», «Закончить игру» с «Оплаченное время не возвращается» (№45), кто за столом, напоминания Web Push; выбор после `interrupted` |
| `/app/s/{id}/receipt` | чек; на iPhone без «На экран Домой» — подсказка про напоминания (после первой игры) |
| `/app/privacy` | заглушка политики: «Текст готовит юрист» (пока нет `docs/legal/privacy.md`) |
| `/app/s/{id}/bar` | бар (M2, отдельный чанк): меню без алкоголя (его не отдаёт сервер, №76), разделы, модификаторы, корзина, «В счёт стола» или «Оплатить сейчас» (СБП, карта), статус заказа по SSE `order` («Принят → Готовится → Готов → Выдан»), счёт стола и его оплата — и после игры (№79) |
| `/app/orders/{id}` | возврат после онлайн-оплаты заказа (`return_url` backend-pos): ждём подтверждения, затем статус |
| `/app/sessions/{id}/tab` | счёт стола: оплата или «Счёт стола оплачен» после возврата с ЮKassa |
| `/app/book`, `/app/book/{club}` | бронь (M3, отдельный чанк): день → время на **борт-шкале** (метки на борту — часы, занятые деления заштрихованы, выбранный интервал светится лампой; каждое деление — переключатель с подписью, стрелки, прокрутка внутри блока) → стол на плане зала (свободные тёмные, выбранный — янтарная рамка) → длительность → цена по тарифу стола и предоплата по правилам клуба. Клуб — из списка (`GET /api/clubs`, предложено) или тот, где гость открывал стол по QR |
| `/app/bookings`, `/app/bookings/{id}` | мои брони (ближайшие и прошедшие); бронь: предоплата, как начать, удержание, отмена по правилам (`cancel` сервера). Ссылки «Моя бронь» из уведомлений сервера |
| `/app/waitlist/{id}` | предложение из листа ожидания (ссылка из уведомления): таймер 5 минут, «Занять стол» |
| `/app/me`, `/app/me/notify` | профиль: часы пакетов на балансе (партии со сроками), покупка пакета; каналы уведомлений — основной и порядок (MAX, Telegram, Web Push), подсказка iPhone «На экран Домой» |

На экране «Стол» (M3): своя бронь на этот стол — «Ваша бронь на 21:00 — Начать игру по брони» (`POST /api/bookings/{id}/start {code}`, ранний приход — доплата); занятый стол — «Сообщить, когда освободится», место в очереди, предложение на 5 минут с таймером и «Занять стол» (стол держится 3 минуты, дальше обычная оплата). Продление перед бронью — «Стол забронирован на 21:00, можно продлить до 20:55» и вариант «До 20:55» (`extend_limit_until`, `booking_conflict`). Оплата часами пакета — котировка `use_balance: true`, способ `balance` или доплата остатка; можно «Оплатить без часов пакета».

На экране «Игра» — кнопка «Бар» и полоса текущего заказа и счёта стола; после игры — «Счёт бара не оплачен» с переходом к оплате.

## Как устроено

- `src/lib/` — логика без JSX (проверяется `node --test`): `game.js` (состояние таймера по `paid_until`, `grace_until`, поправка часов по `remaining_ms`), `words.js` (склонения через `plural`), `auth.js` (вход через бота, вход разработки, согласие), `api.js` (вызовы контракта поверх `@billiardum/shared/api`), `platform.js`, `urls.js`, `routes.js`.
- `src/screens/`, `src/components/` — экраны на Preact. Рисунок стола и статусы — `@billiardum/shared/hall`, тексты ошибок — `@billiardum/shared/errors`.
- Живые обновления — SSE `GET /api/stream?session=…` (событие `session`), при разрыве переподключение и перечитывание сессии, запасной опрос раз в 30 с.
- Вход: «Войти через MAX/Telegram» → `POST /api/auth/bot-link` → ссылка на бота → опрос `GET /api/auth/bot-link/{nonce}`. В PWA сессия — только cookie `bl_session` (`Path=/api`, §14), токены из ответов не храним; после входа — «Вы вошли как … Не вы? Выйти». Мини-приложение Telegram: `init_data` из `#tgWebAppData`, без внешнего скрипта (CSP); там `Bearer` в `sessionStorage` и одноразовый токен потока `POST /api/stream/token`. Согласие — версия из `GET /api/me` → `user.consent.version`. В разработке — вход по телефону (`POST /api/auth/dev`), в сборке без `VITE_DEV_LOGIN=1` формы нет.
- Оплата: ключ `Idempotency-Key` живёт до ответа (повтор после обрыва не создаёт второй платёж); переход только на https-адрес `confirmation.url`.
- Web Push: ключ `GET /api/push/vapid-public-key`, подписка — `PushSubscription.toJSON()` в `POST /api/push/subscribe`.
- PWA: `public/manifest.webmanifest`, значки (SVG и PNG, без эмодзи), `src/sw.js` → `dist/sw.js` (плагин `scripts/sw-plugin.mjs` подставляет список файлов оболочки). Кэшируется только статика, `/api/`, `/t/`, `/pay/` — никогда. Push: тело `{title, body, url, tag}` без персональных данных (№53).
- CSP `default-src 'self'`: без встроенных скриптов и атрибутов `style` в HTML; тема до первой отрисовки — `public/theme-init.js`.

## Заглушка API (`VITE_MOCK=1` или `--mode mock`)

`src/mock/` — поддельный сервер по контракту (состояние в `sessionStorage`, страница «ЮKassa» `/app/mock-pay/{id}`). В обычную сборку не попадает: условие `__BL_MOCK__` сворачивается при сборке, `npm run size` ищет метку `BL_MOCK_MARKER`.

Сценарии — параметр `?mock=` при открытии любой страницы: `anon`, `fresh` (вход без согласия), `user`, `game`, `warn`, `grace`, `unlimited`, `interrupted`, `closed`, `notpayer`, `decline` (ресепшн отклонит заявку), `limit`; бар (`src/mock/bar.js`): `barorders` (игра, заказы и счёт стола), `closedtab` (игра закончилась, счёт не оплачен). Бар «готовит» сам: через 20 с — «Готовится», через минуту — «Готов».
M3 (`src/mock/m3.js`, вид ответов — как `server/bookings`, `server/waitlist`, `server/packages`, `server/payments/quotes.mjs`): `book` (брони и часы на балансе), `mybooking` (стол 4: ваша бронь через 10 минут), `early` (бронь через 50 минут — ранний приход с доплатой), `waitlist` (стол 7: вы в очереди, через 8 секунд — предложение), `balance` (5 часов на балансе), `limit` (продление до брони).
Коды столов: `4K7P9QW2XM` (стол 4, свободен), `6C2J7MD5KT` (6, свободен), `7H3D2RT9QF` (7, занят), `2M8X4KZ6CB` (оплачивают), `5S9N3VJ7AE` (сервис), `8F6T1YH4RD` (нет связи), `3B5R8WA2NP` (бронь). Сессия сценариев — `/app/s/6f1c2a9e-0d4b-4c7e-9a51-3b2f8e7d4c10`.

## M3: что ждём от сервера

- `GET /api/clubs` — публичный список клубов с бронью (`id, name, timezone, city`). Пока его нет, бронь и пакеты открываются для клуба, где гость был по QR.
- Живой канал гостя без сессии (например `GET /api/stream?me=1`): события `waitlist` и `booking` идут в `user:{id}`, но открыть поток можно только с `club` или `session`. Пока — опрос `GET /api/me/waitlist` раз в 5 секунд.
- В записи очереди — `resource.code` (код стола с QR): из уведомления «Занять стол» сразу на выбор времени. Пока код берём из истории этого браузера, иначе просим отсканировать QR.
- `return_url` у пакета часов и предоплаты брони — `/app/me?paid=package` и `/app/bookings/{id}` (сейчас общий `/app/wait/{payment_id}`; экран ожидания сам ведёт в профиль или к брони по сохранённому шагу).
- Флаг подписки Web Push в `GET /api/me` → `channels.webpush` (сейчас видим только подписку этого устройства).
