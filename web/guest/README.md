# @billiardum/web-guest — приложение гостя

PWA по адресу `/app/` (Vite + Preact, JS ESM, без UI-библиотек — decisions №51). Экраны M1 по `docs/contracts/m1.md` §10, дизайн — `docs/DESIGN.md` («Свет над столом»): сверху всегда тёмный зал со столом и лампой, ниже — выбор и действия под большой палец.

## Запуск

```sh
npm run dev:mock -w web/guest     # заглушка API, без сервера: http://127.0.0.1:5173/app/
npm run dev -w web/guest          # настоящий API: прокси /api → BL_API_URL (по умолчанию http://127.0.0.1:3000)
npm run build -w web/guest        # dist/ для Caddy (/app/* → web/guest/dist); стенд разработки: VITE_DEV_LOGIN=1 — форма входа по телефону
npm run size -w web/guest         # сборка + бюджет < 200 КБ JS gzip на первую загрузку, нет заглушки и внешних адресов
npm test -w web/guest             # node --test: логика таймера, слова, вход, адреса, маршруты, заглушка
```

Сейчас первая загрузка — около 35 КБ JS gzip; бар — отдельный чанк (~6 КБ gzip), грузится при открытии.

## Экраны и маршруты

| Путь | Экран |
|---|---|
| `/app/` | текущие игры или «Отсканируйте QR-код на столе» |
| `/app/t/{code}` | «Стол»: номер, тип, статус словом, цена сейчас и дальше, 1/2/3 ч или «Без лимита»; шаги `?step=signin`, `consent`, `pay` на той же странице. Занятый стол — «Стол занят до 21:40» и «Я играю за этим столом» |
| `/app/wait/{payment_id}` | `return_url` ЮKassa: «Ждём подтверждения» → «Включаем свет…» до появления сессии → «Игра» |
| `/app/r/{request_id}` | «Оплачу на ресепшене»: что сказать администратору, срок заявки, отказ или сгорание |
| `/app/s/{id}` | «Игра»: таймер на полэкрана моноширинным, янтарный за 5 минут, красный в льготу (лампа приглушается), «Продлить», «Закончить игру» с «Оплаченное время не возвращается» (№45), кто за столом, напоминания Web Push; выбор после `interrupted` |
| `/app/s/{id}/receipt` | чек; на iPhone без «На экран Домой» — подсказка про напоминания (после первой игры) |
| `/app/privacy` | заглушка политики: «Текст готовит юрист» (пока нет `docs/legal/privacy.md`) |
| `/app/s/{id}/bar` | бар (M2, отдельный чанк): меню без алкоголя (его не отдаёт сервер, №76), разделы, модификаторы, корзина, «В счёт стола» или «Оплатить сейчас» (СБП, карта), статус заказа по SSE `order` («Принят → Готовится → Готов → Выдан»), счёт стола и его оплата — и после игры (№79) |
| `/app/orders/{id}` | возврат после онлайн-оплаты заказа (`return_url` backend-pos): ждём подтверждения, затем статус |
| `/app/sessions/{id}/tab` | счёт стола: оплата или «Счёт стола оплачен» после возврата с ЮKassa |
| `/app/book`, `/app/book/{club}` | бронь (M3, отдельный чанк): день → время на **борт-шкале** (метки на борту — часы, занятые деления заштрихованы, выбранный интервал светится лампой; каждое деление — переключатель с подписью, стрелки, прокрутка внутри блока) → стол на плане зала (свободные тёмные, выбранный — янтарная рамка) → длительность → цена по тарифу стола и предоплата по правилам клуба. Клуб — из списка `GET /api/clubs` (№120) |
| `/app/bookings`, `/app/bookings/{id}` | мои брони (ближайшие и прошедшие); бронь: предоплата, как начать, удержание, отмена по правилам (`cancel` сервера). Ссылки «Моя бронь» из уведомлений сервера |
| `/app/waitlist/{id}` | предложение из листа ожидания (ссылка из уведомления): таймер 5 минут, «Занять стол» |
| `/app/club-request/{id}?t=…` | ответ клуба без программы на заявку гостя — ссылка «Ответить на заявку» из уведомления клубу, без входа (Д1): `GET /api/clubs/requests/{id}/answer?t=` — дата, время (по поясу клуба `timezone`), длительность, гостей, пожелания, телефон гостя как его отдал сервер; «Принять заявку» и «Отказать» с текстом ответа (`POST …/answer {t, decision, text?}`). Ссылка живёт 24 часа (дальше 404 — «Ссылка не работает»); решённая заявка — 409 `request_closed {status}`: «На заявку уже ответили» (accepted, declined), «Заявка у оператора» (operator), «Заявка закрыта» (closed). Отметка браузера (`bl-club-answer:{id}`, только решение и время) добавляет «Вы уже ответили на эту заявку» и что ответили |
| `/app/me`, `/app/me/notify` | профиль: часы пакетов на балансе (партии со сроками), покупка пакета; каналы уведомлений — основной и порядок (MAX, Telegram, Web Push), подсказка iPhone «На экран Домой» |

На экране «Стол» (M3): своя бронь на этот стол — «Ваша бронь на 21:00 — Начать игру по брони» (`POST /api/bookings/{id}/start {code}`, ранний приход — доплата); занятый стол — «Сообщить, когда освободится», место в очереди, предложение на 5 минут с таймером и «Занять стол» (стол держится 3 минуты, дальше обычная оплата; обновления — поток гостя `?me=1`). Продление перед бронью — «Стол забронирован на 21:00, можно продлить до 20:55» и вариант «До 20:55» (`extend_limit_until`, `booking_conflict`). Оплата часами пакета — котировка `use_balance: true`, способ `balance` или доплата остатка; можно «Оплатить без часов пакета».

На экране «Игра» — кнопка «Бар» и полоса текущего заказа и счёта стола; после игры — «Счёт бара не оплачен» с переходом к оплате.

## Движение (DESIGN §6, №127)

- Главная: «разбой при прокрутке» — `components/BreakTable.jsx` (отдельный чанк, ~3 КБ gzip) и `lib/break-sim.js`: одна детерминированная симуляция при загрузке (16 шаров русской пирамиды, отскоки от бортов, шесть луз), кадр — по прогрессу прокрутки первого экрана, назад — шары собираются. Без прокрутки (широкий экран) разбой проигрывается сам один раз. `prefers-reduced-motion` — собранная пирамида.
- Лампа загорается переходом `--lit` за 0,6 с (`TableArt`: первый кадр тёмный), за 10 минут до конца игры мягко пульсирует; кольцо оставшегося времени на сукне вокруг лампы (`timeLeftShare`).
- Оплата прошла — шар закатывается в лузу (`PocketDrop` на экране ожидания), затем загорается лампа над столом.
- Переход экранов — появление 180 мс; нажатие кнопки — «удар кия»; загрузка — тёплое мерцание сукна (`.loading`).

## Как устроено

- `src/lib/` — логика без JSX (проверяется `node --test`): `game.js` (состояние таймера по `paid_until`, `grace_until`, поправка часов по `remaining_ms`), `words.js` (склонения через `plural`), `auth.js` (вход через бота, вход разработки, согласие), `api.js` (вызовы контракта поверх `@billiardum/shared/api`), `platform.js`, `urls.js`, `routes.js`.
- `src/screens/`, `src/components/` — экраны на Preact. Рисунок стола и статусы — `@billiardum/shared/hall`, тексты ошибок — `@billiardum/shared/errors`.
- Живые обновления — SSE `GET /api/stream?session=…` (событие `session`), при разрыве переподключение и перечитывание сессии, запасной опрос раз в 30 с.
- Вход: «Войти через MAX/Telegram» → `POST /api/auth/bot-link` → ссылка на бота → опрос `GET /api/auth/bot-link/{nonce}`. В PWA сессия — только cookie `bl_session` (`Path=/api`, §14), токены из ответов не храним; после входа — «Вы вошли как … Не вы? Выйти». Мини-приложение Telegram: `init_data` из `#tgWebAppData`, без внешнего скрипта (CSP); там `Bearer` в `sessionStorage` и одноразовый токен потока `POST /api/stream/token`. Согласие — версия из `GET /api/me` → `user.consent.version`. В разработке — вход по телефону (`POST /api/auth/dev`), в сборке без `VITE_DEV_LOGIN=1` формы нет.
- Оплата: ключ `Idempotency-Key` живёт до ответа (повтор после обрыва не создаёт второй платёж); переход только на https-адрес `confirmation.url`.
- Web Push: ключ `GET /api/push/vapid-public-key`, подписка — `PushSubscription.toJSON()` в `POST /api/push/subscribe`.
- PWA: `public/manifest.webmanifest`, значки (SVG и PNG, без эмодзи), `src/sw.js` → `dist/sw.js` (плагин `scripts/sw-plugin.mjs` подставляет список файлов оболочки). Кэшируется только статика, `/api/`, `/t/`, `/pay/` — никогда. Push: тело `{title, body, url, tag}` без персональных данных (№53).
- CSP `default-src 'self'`: без встроенных скриптов и атрибутов `style` в HTML; тема до первой отрисовки — `public/theme-init.js`.

## Заглушка API (`VITE_MOCK=1` или `--mode mock`)

`src/mock/` — поддельный сервер по контракту (состояние в `sessionStorage`, страница «ЮKassa» `/app/mock-pay/{id}`). В обычную сборку не попадает: условие `__BL_MOCK__` сворачивается при сборке, `npm run size` ищет метку `BL_MOCK_MARKER`.

Сценарии — параметр `?mock=` при открытии любой страницы: `anon`, `fresh` (вход без согласия), `user`, `game`, `warn`, `grace`, `unlimited`, `interrupted`, `closed`, `notpayer`, `decline` (ресепшн отклонит заявку), `limit`; бар (`src/mock/bar.js`): `barorders` (игра, заказы и счёт стола), `closedtab` (игра закончилась, счёт не оплачен). Бар «готовит» сам: через 20 с — «Готовится», через минуту — «Готов».
M3 (`src/mock/m3.js`, вид ответов — как `server/bookings`, `server/waitlist`, `server/packages`, `server/payments/quotes.mjs`): `book` (брони и часы на балансе), `mybooking` (стол 4: ваша бронь через 10 минут), `early` (бронь через 50 минут — ранний приход с доплатой), `waitlist` (стол 7: вы в очереди, через 8 секунд игра на нём закончится и придёт предложение — событием потока `?me=1`), `balance` (5 часов на балансе), `limit` (продление до брони).
M4 (`src/mock/m4.js`): `plus`, `plusnew` (ника нет: на турнире вместо «Записаться» — форма ника, №150), `plusgame`, `tour`; `clubrequest` — две заявки гостей в клуб без программы, ответ клуба по ссылке без входа: `/app/club-request/c3000000-0000-4000-8000-000000000001?t=mock-answer-token-0123456789` (новая) и `/app/club-request/c3000000-0000-4000-8000-000000000002?t=mock-answer-token-operator-01` (уже у оператора); `pluslimit` — у гостя уже 6 засчитанных партий за сутки (№148): следующая партия «в рейтинг не засчитана — лимит партий за сутки» (`not_counted_reason: 'player_daily_limit'`), обоим игрокам заглушка пишет уведомление `plus.match_not_counted`; `plusrace` — игра на столе 4, Андрей внёс счёт 8:5 и переписывает его на 8:3, пока вы подтверждаете: первое «Подтвердить счёт» даёт 409 `score_changed`, карточка показывает свежий счёт и «Соперник изменил счёт — проверьте ещё раз» (M4-3). Подтверждение партии и матча турнира отправляет показанный счёт `{ score_a, score_b }` (`shownMatchScore`, `shownTournamentScore` в `lib/plus.js`); заглушка отвечает 409, если он не совпадает с текущим.
Коды столов: `4K7P9QW2XM` (стол 4, свободен), `6C2J7MD5KT` (6, свободен), `7H3D2RT9QF` (7, занят), `2M8X4KZ6CB` (оплачивают), `5S9N3VJ7AE` (сервис), `8F6T1YH4RD` (нет связи), `3B5R8WA2NP` (бронь). Сессия сценариев — `/app/s/6f1c2a9e-0d4b-4c7e-9a51-3b2f8e7d4c10`.

## M3: живой API (волна B, №119–120)

- Клубы для брони — `GET /api/clubs` без входа (`id, name, city, address, timezone, plan`); клуб, где гость был по QR, — первым. Без связи — хотя бы он.
- Поток гостя без сессии — `GET /api/stream?me=1` (в мини-приложении — одноразовый токен `POST /api/stream/token {me: true}`): события `booking` и `waitlist`, вид — в `data.type` (`booking.confirmed|reserved|started|expired|canceled`, `waitlist.offered|accepted|updated`). Экраны стола, предложения очереди, брони и «Мои брони» перечитывают данные по событию и при каждом переподключении; пока поток оборван — опрос раз в 5 секунд (`src/lib/live.js`).
- Кода стола в очереди нет (№119): «Занять стол» из уведомления — экран «Стол держим до 21:03 — отсканируйте QR на столе». На самом экране стола (гость уже у QR) — сразу выбор времени и оплата.
- `return_url`: предоплата брони — `/app/bookings/{id}?paid=1` (экран брони ждёт подтверждения), пакет — `/app/me?paid=package` (профиль ждёт, пока вырастет баланс). Экран ожидания `/app/wait/{payment_id}` остаётся для игры.
- Каналы уведомлений — `user.channels {max, telegram, webpush}` из `GET /api/me`.
- Исправления по tester (№122–123, №126): в «Уведомлениях» — только каналы из `user.channels_available` (MAX, пока он на сервере заглушка, не показываем); основной по умолчанию — сохранённый, если доступен, иначе первый подключённый, иначе первый доступный. Стол, предложенный гостю из очереди, держится за ним (`reserved`): гость «с улицы» видит «Стол ждёт гостя до HH:MM» и `table_busy`. Причина по `close_reason` записи очереди: `released` — «Стол отдали гостю у стойки, вы можете снова встать в очередь», `expired` — «Вы не ответили за 5 минут», `table_taken` — «Стол успели занять, вы остаётесь в очереди на своём месте» (экран предложения, экран стола); без поля — общий текст. Игра по брони кончается ровно в конце брони, доплату считает сервер.

## Исправления приёмки M4

- Д4: «Счёт неверный» — только у партии `pending` и только тому, кто её ещё не подтвердил (`canDispute` в `lib/plus.js`); у подтверждённой кнопки нет (сервер ответил бы 409 `match_not_pending`).
- Д5: сетка турнира прокручивается только внутри себя: `.bracket` и `.bm` — `position: relative`, скрытые подписи «— победа» (`position: absolute`) больше не выходят за край и не дают прокрутку страницы на 360 px.
- №150: запись на турнир только с ником Бильярдум+. Ника нет (`GET /api/plus/me` → `nick: null` или запись ответила 409 `no_profile`) — вместо «Записаться» блок «Создайте ник, чтобы участвовать» с полем ника; «Сохранить ник и записаться» создаёт профиль (`PATCH /api/plus/me`) и сразу продолжает запись (со взносом — переход к оплате).
- Стол турнира (№146, `c5fe9b9`): котировка продления, не помещающегося до турнира, — 409 `table_busy {reason: 'tournament', busy_until}`; в окне «Продлить» — «Продлить нельзя: на столе турнир с HH:MM» (начало — `extend_limit_until` сессии + 5 минут; без предела — «до» `busy_until`), экран не перечитывается. Подсказка над вариантами — `extendLimitText` (`shared/booking.mjs`): бронь (`next_booking_at`) — «Стол забронирован на…», турнир (после 409 или `extend_limit_by: 'tournament'`) — «На столе турнир с…», иначе нейтрально «Стол занят с 21:00, можно продлить до 20:55» (сессия не говорит, бронь впереди или турнир). Бронь в окне турнира — «Стол занят турниром до HH:MM» по поясу клуба (`ErrorNote timeZone`). Заглушка: `?mock=tourlimit`.
- Матч `canceled` (турнир отменили): в сетке «Отменён» без стола, в «Вашем матче» — «Матч отменён», счёт не вносится.
- Д9: «Камбэк» не рекламируется (№145): в настройках приватности пример — «Сухая», «Ночная смена»; в списке достижений он виден, только если уже получен.

## M5.1: тестовый режим клуба

На экранах стола (с шагом оплаты), ожидания оплаты и игры — плашка «Тестовый режим клуба — деньги не списываются» (`components/TestModeNote.jsx`, `lib/testmode.js`). Признак — `club.mode === 'test'` в `GET /api/t/{code}` и `GET /api/sessions/{id}` или `is_test` у сессии и платежа (допущение M5.1: контракт поле не назвал). Экран ожидания берёт признак из `flow.testMode` стола. Заглушка: `?mock=testclub` (стол), `?mock=testgame` (идущая игра). Код — в основном чанке, первая загрузка +1,4 КБ gzip (52,6 КБ из 200).
