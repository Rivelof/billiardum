# @billiardum/web-admin — программа клуба

Адрес `/club/` (Vite + Preact, JS ESM, без UI-библиотек — decisions №51). Экраны M1 по `docs/contracts/m1.md` §10, M2 (касса, бар, смены, склад, меню, ККТ) — по `docs/contracts/m2.md` и коду backend-pos и backend-kkt. Владелец и управляющий — сначала телефон (разделы снизу), ресепшн — планшет горизонтально (разделы слева, очередь и зал рядом, крупные плитки, всё с клавиатуры и пальцем).

## Запуск

```sh
npm run dev:mock -w web/admin     # заглушка API: http://127.0.0.1:5174/club/
npm run dev -w web/admin          # настоящий API: прокси /api → BL_API_URL (по умолчанию http://127.0.0.1:3000)
npm run build -w web/admin        # dist/ для Caddy (/club/* → web/admin/dist)
npm test -w web/admin             # node --test: сдача, сутки клуба, журнал, тревоги, зал, касса (скидка, лимит, тело продажи), смена (расхождение, отчёт), склад (ревизия), CSV, заглушка
```

## Экраны

| Путь | Кто | Что |
|---|---|---|
| `/club/signin` | все | вход по телефону через бота MAX или Telegram; в разработке — по номеру |
| `/club/pin` | терминал | быстрая смена сотрудника по PIN (4–6 цифр, экранная клавиатура) |
| `/club/c/{club}/reception` | ресепшн и выше | очередь «Стол 4 · 2 ч · 1 600 ₽» со звуком (WebAudio, без файлов), «Принять оплату» (наличные — ввод суммы, быстрые суммы, сдача крупно; карта через терминал), «Отклонить» с причиной; зал, стол → «Сервисный свет» (причина и текст обязательны) |
| `/club/c/{club}/now` | владелец, управляющий | тревоги сверху с «Принято», зал, выручка за сегодня по способам оплаты; стол → «Продлить без оплаты» с причиной |
| `/club/c/{club}/journal` | владелец, управляющий | журнал: период, действие, стол, сотрудник; «Проверить цепочку» (владелец) |
| `/club/c/{club}/alarms` | владелец, управляющий | открытые тревоги |
| `/club/c/{club}/devices` | владелец, управляющий, монтажник | «Контроллеры»: на связи ли, сигнал словом, прошивка, возможности, «Подсветить стол» (identify); «Добавить контроллер» — номер и код с наклейки вручную и стол → окно привязки 30 минут (№67), экран ждёт, пока контроллер выйдет на связь. Привязка — владелец и монтажник |
| `/club/c/{club}/pos` | ресепшн и выше | касса POS (планшет 1280×800): плитки по категориям, поиск, вкладка «Столы» (заявки гостей и открытые счета столов), модификаторы, чек с количеством, скидка (лимит клуба `pos/settings`; выше — причина, ресепшну — PIN управляющего), оплата наличными (клавиатура, быстрые суммы, сдача крупно), картой через терминал, по СБП (QR из `confirmation_data`, ожидание по SSE `pos_sale` и опросу); состояние чека ККТ и «Касса не на связи, чек пробьётся позже»; «Стоп-лист» (№88); без открытой смены касса не продаёт |
| `/club/c/{club}/bar` | бар, ресепшн и выше | экран бара (ТВ или планшет, всегда тёмный зал): «Новые», «Готовятся», «Готовы», стол, позиции с модификаторами, время ожидания словами, смена статуса одним касанием, звук нового заказа (WebAudio) |
| `/club/c/{club}/shift` | ресепшн и выше | смена: открыть с разменом; закрыть с фактом наличных — «Должно быть», расхождение крупно, при ≠ 0 — повторный пересчёт; без ожидаемой суммы от сервера — «слепое» закрытие и расхождение после. Управляющему и владельцу — список смен |
| `/club/c/{club}/shift/{id}` | управляющий, владелец | отчёт смены: наличные и расхождение, сверка ККТ и онлайн до копейки, выручка столов и бара по способам оплаты, часы игры и загрузка, сервисный свет по сотрудникам и столам, ручные действия |
| `/club/c/{club}/stock` | управляющий, владелец | склад: остатки, приход с ценой закупки, списание с причиной, ревизия «факт против расчёта» с расхождением в деньгах |
| `/club/c/{club}/menu` | управляющий, владелец | меню: товары по категориям, стоп-лист одним касанием, товар (цена, единица, НДС, предмет расчёта, алкоголь, учёт остатка, модификаторы), группы модификаторов, загрузка из CSV с превью и ошибками по строкам |
| `/club/c/{club}/kkt` | управляющий, владелец | касса ККТ: состояние и очередь чеков («исход неизвестен» — «Повторить» или «Чек есть на ленте» с ФД и ФП и причиной); владельцу — мосты, «Выдать токен моста» (токен один раз) и инструкция запуска `tools/kkt-bridge` |
| `/club/c/{club}/more` | все | имя сотрудника (`PATCH /api/me`), свой PIN для терминала (`PUT /api/staff/pin`), QR-наклейки PDF, регистрация терминала ресепшена, выход |

Звук заявок и заказов бара браузер разрешает только после касания экрана: первое касание включает его, кнопки «Включить звук заявок» и «Включить звук заказов» — явно.

Навигация: ресепшн — Касса, Ресепшн, Бар, Смена, Ещё. Владелец и управляющий на телефоне — Сейчас, Смены, Журнал, Тревоги, Ещё (касса, бар, склад, меню, ККТ и контроллеры — в «Ещё» и в боковой панели планшета).

## Как устроено

- `src/lib/` — логика без JSX: `pos.js` (скидка как у сервера — целый процент, «половина вверх» до копейки, только на бар; лимит; тело `POST /api/pos/sales`; вид продажи и кассы ККТ; чек словами), `shift.js` (ожидаемые наличные, расхождение, отчёт), `stock.js` (количество до тысячных, ревизия в деньгах), `csv.js` (CSV меню и ошибки сервера словами), `cash.js` (ввод суммы, сдача, быстрые суммы, клавиатура — целые копейки), `zone.js` (сутки клуба по его поясу для фильтра журнала), `audit.js` (действия журнала словами, группы фильтра), `alarms.js`, `sound.js`, `hall.js`, `auth.js` (роли), `api.js`.
- План зала — `src/components/HallPlan.jsx` на `@billiardum/shared/hall`: столы в настоящих пропорциях, свободные тёмные, занятые освещены, у каждого стола подпись словом и метка для диктора.
- Живые обновления — SSE `GET /api/stream?club=…` (`hall`, `reception_request`, `alarm`, `session`), при разрыве — переподключение и перечитывание, запасной опрос.
- Вход — cookie `bl_session` (§14); клуб для маршрутов без `{club}` — заголовок `X-Club-Id` во всех запросах.
- Терминал: `POST /api/staff/terminal` → `terminal_token` в `localStorage`; `GET /api/staff/terminal` и `POST /api/staff/pin` получают его как `Authorization: Bearer`. После PIN сервер сам ставит cookie сотрудника.
- «Принять оплату»: сервер отвечает `session_id: null` (сессия создаётся асинхронно) — окно ждёт стол в зале по SSE `hall` и опросу и пишет «Свет на столе N включён».
- Журнал: фильтр `action` списком через запятую (§14); если сервер его ещё не принимает (`400`), программа переходит на старый вид (`session.`) или фильтрует на клиенте.

- Корзина POS из `@billiardum/shared/bar` (меню, модификаторы, строки), живёт в `sessionStorage` до оплаты. Ключ идемпотентности продажи — на одно окно оплаты.
- QR для СБП — `uqr` (MIT), SVG без атрибутов `style`, всегда тёмные модули на светлом поле.

## Заглушка API (`VITE_MOCK=1` или `--mode mock`)

`src/mock/` — поддельный сервер по контракту, новая заявка приходит раз в минуту (слышно звук). Сценарии `?mock=`: `reception` (по умолчанию), `owner`, `manager`, `anon`, `empty`, `broken` (цепочка нарушена), `terminal` (устройство — терминал; PIN `1234`); M2 (`src/mock/m2.js`, вид ответов — как у backend-pos и backend-kkt): `pos` (смена открыта), `noshift`, `kktoff` (касса ККТ не на связи, чек «исход неизвестен»; `kktoff-owner` — то же под владельцем), `bar` (бармен). PIN управляющего для скидки — `1234`; СБП «оплачивается» через 9 секунд, чек ККТ пробивается через 2,5 секунды, новый заказ со стола — раз в 75 секунд. Клуб: `/club/c/0b6b8c1e-5a7d-4f0e-9c3a-2d1e4f5a6b7c/…`. Вход разработки: номер на `…01` — владелец, `…02` — управляющий, `…05` — бар, остальные — ресепшн.

## M2: что программа ждёт от сервера сверх сделанного (волна B)

Экраны работают и без этих полей (запасной путь описан), но с ними — как задумано:

- `GET /api/clubs/{club}/shifts/current` — в открытой смене `expected_cash_kopecks`, `cash_sales_kopecks`, `cash_refunds_kopecks` «на сейчас». Без них закрытие «слепое»: кассир вводит факт, ожидаемое и расхождение видит после закрытия.
- Скидка выше лимита у ресепшена — подтверждение управляющим по PIN на этом терминале: `GET /api/clubs/{club}/staff/approvers` → `[{user_id, name, role}]`, `POST /api/pos/discount-approvals {user_id, pin, discount_kopecks, base_kopecks, percent?, reason_code, reason_text}` → `{approval_id, approved_by}`, в продаже `discount.approval_id`. Сейчас сервер отвечает ресепшену `limit_exceeded` — экран просит управляющего провести продажу самому.
- `POST /api/pos/sales/{id}/cancel` — отменить QR СБП, если гость передумал. Без него окно закрывается, а касса следит за продажей по `pos_sale`: пришла оплата — чек закрывается сам.
- `GET /api/clubs/{club}/pos/settings` — читать ресепшену (лимит скидки); без доступа — 10 %.
- В продаже `receipt_fd`, `receipt_fp` после печати — «Чек пробит, ФД № …».
- В отчёте смены — по желанию `play.by_resource` (загрузка по столам) и номер стола в `manual_actions.items[]`; в списке смен — `revenue_total_kopecks`.
- Роль `bar` для отдельного планшета бара (экран уже пускает её); пока бар открывают под ресепшном.
