# Симулятор контроллера стола (`@billiardum/device-sim`)

Поднимает по виртуальному контроллеру на каждое устройство из файла устройств и говорит с брокером по протоколу `docs/protocol.md` (v1), как прошивка ESP32. На нём работают backend, tester и pentester, пока нет железа (decisions №7).

Свою реализацию протокола держит в `lib/` и ничего не импортирует из `server/`. Так общие векторы `docs/protocol-vectors.json` ловят расхождения между сервером и контроллером.

## Что умеет в M0

- Читает файл устройств (контракт M0 §4) и подключается к брокеру по TLS с CA. Client id и логин MQTT — `device_id`, пароль берётся из файла.
- Ставит Last Will `offline` (retained, QoS 1) в `status`. После подписки на `cmd` публикует `online` (retained), затем `state`.
- Публикует `state` (retained, QoS 1) при изменении и раз в 60 с. Поля — по §4, включая `caps`, `fw`, `boot`, `last_seq`.
- При старте шлёт событие `boot` с `boot` и `n` и данными `fw`, `caps`, `reset_reason`. События лежат в кольцевом буфере NVS, пока брокер не подтвердит их (PUBACK). Если связи нет, они досылаются после подключения.
- Проверяет команды строго по §3.1–§3.2:
  - разбор и канонизация (числа проверяются по исходному тексту через `context.source` reviver);
  - `bad_format`;
  - HMAC-SHA256, сравнение через `crypto.timingSafeEqual`;
  - таблица повторов: на точный повтор отвечает сохранённым `ack` байт в байт и команду не исполняет.
- Исполняет `ping` (`ack` и внеочередной `state`) и `identify` (индикатор `identify` на `duration_ms`). Остальные типы проходят все проверки и получают `unknown_type` до M1.
- Пишет лог строками JSON без секретов.

В M1 добавятся сессии и сигналы по `warn_ms` и `grace_ms`, перезагрузка (правило 4 §5), датчик тока и режимы сбоя.

## Запуск

```sh
npm run sim                                  # из корня, по deploy/dev/devices.json
npm start -w tools/device-sim -- --tables 1,4 --fault bypass@4
node tools/device-sim/index.mjs --help
```

Файл устройств создаёт backend: `npm run provision:dev`. В Docker Compose симулятор запускает `npm run dev` (сервис `device-sim`).

| Переменная | Что задаёт |
|---|---|
| `SIM_DEVICES_FILE` | файл устройств; по умолчанию `deploy/dev/devices.json` |
| `MQTT_URL` | адрес брокера вместо `mqtt_url` из файла; `mqtts://…`, `mqtt://` только для тестов |
| `MQTT_CA_FILE` | CA брокера вместо `ca_file` из файла |
| `LOG_LEVEL` | `debug`, `info` (по умолчанию), `warn`, `error` |
| `SIM_TABLES` | то же, что `--tables` |
| `SIM_FAULTS` | то же, что `--fault`, через запятую |
| `SIM_CAPS` | то же, что `--caps` |

Относительный путь ищется по порядку: от каталога, где вызвали `npm` (`INIT_CWD`) или от текущего каталога, затем от корня репозитория. Для `ca_file` между этими двумя вариантами проверяется ещё папка файла устройств.

| Флаг | Что делает |
|---|---|
| `--tables 1,4` | поднять только эти столы (`table_number`) |
| `--caps relay,led,buzzer,current,dimmer` | что «есть на плате»; по умолчанию `relay,led,buzzer,current` |
| `--fault <режим>[@<стол>]` | режим сбоя, можно повторять; без `@стол` — для всех столов |

### Режимы сбоя

Флаги уже принимаются, но до M1 симулятор только пишет `sim_fault_not_implemented` и работает штатно.

| Режим | Что будет в M1 |
|---|---|
| `net-drop` | обрыв связи без DISCONNECT, брокер публикует Last Will `offline` |
| `reboot` | перезагрузка: свет выключен, `boot`+1, событие `boot`, правило 4 §5 |
| `bypass` | ток при выключенном реле, событие `bypass_detected` |
| `lamp-fault` | реле включено, тока нет, событие `lamp_fault` |
| `slow-ack` | `ack` с задержкой |
| `replay-old` | повторная подача ранее принятой команды, `replayed_seq` |

## Лог

Строки JSON в stdout: `{"t":"…","level":"…","msg":"…", …}`. Пароль MQTT, `device_key` и подписи в лог не попадают.

| `msg` | Когда |
|---|---|
| `sim_start` | старт: число столов, адрес брокера без логина, TLS, `caps`, режимы сбоя |
| `sim_state` | смена состояния стола: `device_id`, `table`, `mode`, `relay`, `dim`, `led`, `buzzer`, `remaining_ms` (контракт §7) |
| `sim_cmd` | итог команды: `type`, `seq`, `cmd_id`, `result` (`ok`, `resend`, код ошибки), `reason` для `bad_format` и `bad_sig` |
| `mqtt_connected`, `mqtt_disconnected`, `mqtt_error` | связь с брокером; одинаковая ошибка подряд пишется один раз |
| `sim_fault_not_implemented` | задан режим сбоя, который появится в M1 |
| `sim_event` (`debug`) | событие положено в буфер |

## Как симулятор читает протокол там, где v1 молчит

Эти решения вынесены на ревью протокола в M0.

- `state_seq` увеличивается на каждой публикации `state` и сбрасывается при загрузке, порядок задаёт пара (`boot`, `state_seq`). В `ack.state_seq` стоит номер `state`, опубликованного после исполнения команды; `state` уходит раньше `ack`.
- «Изменение» для внеочередного `state` — смена `mode`, `session_id`, `relay`, `dim`, `led` или `buzzer`. Остаток, `uptime_s` и `last_seq` изменением не считаются.
- `buzzer` в `state` — флаг сессии «пищалка разрешена». `dim` — яркость в процентах: 0, если реле выключено. Если в `caps` нет `current`, `current_ma` равен `null`.
- В `ack` после `bad_format` поля `cmd_id` и `seq` повторяются, только если они правильного вида, иначе там `null`.
- Обязательные поля команды: `v`, `id` (UUID), `seq` (целое ≥ 1), `type` (непустая строка), `body` (объект). `issued_at` необязателен, но если есть, должен быть целым.
- `sig` принимается только как строгое base64 от 32 байт: неканоническая запись даёт `bad_sig`. Не-ASCII в `sig` — `bad_format`, как в любой строке.
- Для повторяющегося ключа побеждает последнее значение, как в `JSON.parse`. Подпись считается по разобранному объекту, поэтому значение так не подменить.
- Неверное тело команды, которую симулятор исполняет (`identify` без `duration_ms`), получает `bad_format` на шаге 4: `seq` уже сдвинут. Если в `caps` нет `led`, `identify` отвечает `hw_fault`.
- Пределы симулятора: сообщение не длиннее 4096 байт, вложенность не глубже 8.
- `reset_reason` при старте процесса — `power_on`.

## Устройство

| Файл | Что внутри |
|---|---|
| `index.mjs` | вход: конфиг, логгер, по `SimDevice` на стол, остановка по SIGINT и SIGTERM (сам публикует `offline`) |
| `lib/canonical.mjs` | строгий разбор JSON и каноническая строка (§3.1) |
| `lib/command.mjs` | шаги 1–2 проверки: формат и подпись |
| `lib/replay.mjs` | таблица повторов §3.2 |
| `lib/machine.mjs` | конечный автомат без MQTT; часы и NVS передаются снаружи |
| `lib/modes.mjs` | состояния, индикатор и реле по состояниям, переходы §5 |
| `lib/nvs.mjs` | интерфейс NVS, `MemoryNvs`, кольцевой буфер событий |
| `lib/clock.mjs` | `RealClock` и `FakeClock` для тестов с ускоренным временем |
| `lib/device.mjs` | MQTT: подключение, Last Will, подписка, публикации, досылка событий |
| `lib/config.mjs`, `lib/log.mjs`, `lib/faults.mjs` | файл устройств и переменные, лог JSON, флаги сбоев |

В M0 NVS живёт в памяти процесса. Перезапуск процесса — как контроллер со стёртым NVS: `boot` снова 1, `last_seq` 0. Имитация перезагрузки без перезапуска появится в M1: тот же `MemoryNvs` передаётся новой загрузке `TableMachine.start()`.

## Тесты

```sh
npm test -w tools/device-sim       # юнит-тесты и все векторы, без брокера и Docker
npm run test:it -w tools/device-sim  # с настоящим брокером, нужен Docker
```

`npm test` проверяет:
- все векторы `docs/protocol-vectors.json`: результат и каноническую строку, а ещё проход вектора через автомат до `ack`;
- края канонизации;
- таблицу повторов §3.2;
- автомат на ускоренном времени;
- конфиг и лог.

Интеграционный тест без брокера пропускается.

`npm run test:it` поднимает свой контейнер `bl-sim-mqtt` (`eclipse-mosquitto:2`, порт 18883 на 127.0.0.1) с временным конфигом и удаляет его в конце:
- вход по паролю;
- ACL как у роли Dynamic Security;
- TLS с одноразовым CA, если на хосте есть `openssl` (без него или с `SIM_IT_TLS=0` — `mqtt://`).

Тест запускает `index.mjs` и подписывает команды своей функцией с ключом из теста. Он проверяет:
- `online`, `state` и `boot`;
- `ping` и `ack`, точный повтор и `replayed_seq`;
- `bad_sig` с событием, `identify`, `unknown_type`, `bad_format`;
- что симулятор пишет только в свои топики и что в логе нет секретов;
- отказ TLS без нашего CA;
- Last Will при `kill -9` и `offline` при штатной остановке.

`SIM_IT_KEEP=1` оставляет контейнер и временную папку, `SIM_IT_WORKDIR` задаёт, где её создать.
